# SQL 学习笔记 - 索引与触发器

## 一、索引（Index）

### 1.1 什么是索引

索引是对数据库表中一列或多列的值进行排序的一种结构，类似于书籍的目录。

**作用：**
- 加快查询速度
- 降低数据库IO操作
- 提高排序性能

**代价：**
- 占用额外空间
- 降低插入、更新、删除速度

---

### 1.2 索引类型

| 类型 | 说明 | 使用场景 |
|------|------|----------|
| **普通索引** | 最基本的索引 | 通用场景 |
| **唯一索引** | 索引列值唯一 | 主键、唯一字段 |
| **复合索引** | 多个列组成的索引 | 多列组合查询 |
| **全文索引** | 对文本内容索引 | 全文搜索 |
| **空间索引** | 对空间数据索引 | 地理位置查询 |

---

### 1.3 创建索引

```sql
-- 普通索引
CREATE INDEX idx_email ON users(email);

-- 唯一索引
CREATE UNIQUE INDEX idx_username ON users(username);

-- 复合索引
CREATE INDEX idx_name_age ON users(name, age);

-- MySQL 全文索引
CREATE FULLTEXT INDEX idx_content ON articles(content);

-- PostgreSQL 全文索引
CREATE INDEX idx_content ON articles USING gin(to_tsvector('english', content));

-- 空间索引（PostGIS）
CREATE INDEX idx_location ON places USING gist(location);
```

---

### 1.4 索引命名规范

```
idx_表名_列名    -- 普通索引
uk_表名_列名    -- 唯一索引
fk_表名_列名    -- 外键索引
```

```sql
-- 规范示例
CREATE INDEX idx_users_email ON users(email);
CREATE UNIQUE INDEX uk_users_username ON users(username);
CREATE INDEX idx_orders_user_id ON orders(user_id);
```

---

### 1.5 复合索引

复合索引遵循**最左前缀原则**：

```sql
-- 创建复合索引
CREATE INDEX idx_name_age ON users(name, age);

-- ✅ 可以使用索引的查询
SELECT * FROM users WHERE name = '张三';
SELECT * FROM users WHERE name = '张三' AND age = 25;
SELECT * FROM users WHERE name = '张三' AND age > 20;

-- ❌ 无法使用索引的查询
SELECT * FROM users WHERE age = 25;  -- 跳过最左列
SELECT * FROM users WHERE age = 25 AND name = '张三';  -- 顺序不对

-- ✅ 优化：交换顺序
CREATE INDEX idx_age_name ON users(age, name);
SELECT * FROM users WHERE age = 25;
```

---

### 1.6 索引使用建议

| 场景 | 建议 |
|------|------|
| **主键** | 自动创建索引 |
| **外键** | 自动创建索引 |
| **频繁查询** | 创建索引 |
| **WHERE 条件** | 为常用字段创建索引 |
| **ORDER BY** | 为排序字段创建索引 |
| **JOIN 条件** | 为关联字段创建索引 |
| **低基数列** | 不建议（如性别、状态） |
| **频繁更新** | 慎用 |

```sql
-- ✅ 推荐创建索引
CREATE INDEX idx_email ON users(email);  -- WHERE email = ?
CREATE INDEX idx_order_date ON orders(order_date);  -- WHERE order_date > ?
CREATE INDEX idx_user_id ON orders(user_id);  -- JOIN 条件

-- ❌ 不推荐创建索引
CREATE INDEX idx_gender ON users(gender);  -- 基数太低
CREATE INDEX idx_status ON users(status);  -- 基数太低
CREATE INDEX idx_counter ON logs(counter);  -- 频繁更新
```

### 1.7 查看索引

```sql
-- MySQL 查看索引
SHOW INDEX FROM users;

-- PostgreSQL 查看索引
SELECT indexname, indexdef FROM pg_indexes WHERE tablename = 'users';

-- 查看索引使用情况（MySQL）
SELECT * FROM sys.schema_unused_indexes WHERE object_schema = 'your_database';

-- PostgreSQL 查看索引使用情况
SELECT 
    schemaname,
    tablename,
    indexname,
    idx_scan,
    idx_tup_read,
    idx_tup_fetch
FROM pg_stat_user_indexes
WHERE schemaname = 'public'
ORDER BY idx_scan;
```

---

### 1.8 删除索引

```sql
-- MySQL
DROP INDEX idx_email ON users;

-- PostgreSQL
DROP INDEX idx_email;

-- 或带模式名
DROP INDEX public.idx_email;
```

---

### 1.9 覆盖索引

覆盖索引包含查询所需的所有列，无需回表。

```sql
-- 创建覆盖索引
CREATE INDEX idx_name_age_email ON users(name, age, email);

-- ✅ 使用覆盖索引，无需回表
SELECT name, age, email FROM users WHERE name = '张三';

-- ❌ 需要回表（查询列不在索引中）
SELECT name, age, email, phone FROM users WHERE name = '张三';
```

---

### 1.10 索引失效场景

```sql
-- ❌ 索引失效的场景

-- 1. 对列使用函数
SELECT * FROM users WHERE YEAR(created_at) = 2024;
-- ✅ 优化
SELECT * FROM users WHERE created_at >= '2024-01-01' AND created_at < '2025-01-01';

-- 2. 隐式类型转换
SELECT * FROM users WHERE phone = 13800138000;  -- phone 是 VARCHAR
-- ✅ 优化
SELECT * FROM users WHERE phone = '13800138000';

-- 3. 使用 OR（部分情况）
SELECT * FROM users WHERE email = 'a@example.com' OR phone = '13800138000';
-- ✅ 优化：使用 UNION
SELECT * FROM users WHERE email = 'a@example.com'
UNION
SELECT * FROM users WHERE phone = '13800138000';

-- 4. LIKE 以通配符开头
SELECT * FROM users WHERE name LIKE '%张%';
-- ✅ 优化：全文索引
SELECT * FROM users WHERE MATCH(name) AGAINST('张');

-- 5. NOT IN、!=、<>
SELECT * FROM users WHERE id NOT IN (1, 2, 3);
-- ✅ 优化：使用 NOT EXISTS
SELECT * FROM users u WHERE NOT EXISTS (SELECT 1 FROM tmp WHERE id = u.id);

-- 6. WHERE 和 ORDER BY 使用不同索引
SELECT * FROM users WHERE department_id = 1 ORDER BY salary;
-- ✅ 优化：创建复合索引
CREATE INDEX idx_dept_salary ON users(department_id, salary);
```

---

### 1.11 索引维护

```sql
-- MySQL 分析表
ANALYZE TABLE users;

-- MySQL 优化表
OPTIMIZE TABLE users;

-- PostgreSQL 分析表
ANALYZE users;

-- PostgreSQL VACUUM
VACUUM users;          -- 回收空间
VACUUM FULL users;     -- 完全回收（需锁定表）
VACUUM ANALYZE users;  -- 回收并更新统计信息

-- 重建索引
-- MySQL
ALTER TABLE users ENGINE=InnoDB;  -- 重建表，重建索引

-- PostgreSQL
REINDEX INDEX idx_email;
REINDEX TABLE users;
```

## 二、触发器（Trigger）

### 2.1 什么是触发器

触发器是数据库中一种特殊的存储过程，当特定事件（INSERT、UPDATE、DELETE）发生时自动执行。

**作用：**
- 数据验证
- 自动计算
- 审计日志
- 级联操作

**缺点：**
- 难以调试
- 性能影响
- 业务逻辑分散

---

### 2.2 触发器基本语法

```sql
-- MySQL 语法
CREATE TRIGGER 触发器名
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON 表名
FOR EACH ROW
BEGIN
    -- 触发器逻辑
END;

-- PostgreSQL 语法
CREATE OR REPLACE FUNCTION 触发器函数()
RETURNS TRIGGER AS $$
BEGIN
    -- 触发器逻辑
    RETURN NEW;  -- INSERT/UPDATE 返回新行
    -- 或
    RETURN OLD;  -- DELETE 返回旧行
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER 触发器名
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON 表名
FOR EACH ROW
EXECUTE FUNCTION 触发器函数();
```

---

### 2.3 触发器类型

| 类型 | 说明 | 使用时机 |
|------|------|----------|
| `BEFORE INSERT` | 插入前执行 | 数据验证、默认值设置 |
| `AFTER INSERT` | 插入后执行 | 审计日志、关联更新 |
| `BEFORE UPDATE` | 更新前执行 | 数据验证 |
| `AFTER UPDATE` | 更新后执行 | 审计日志 |
| `BEFORE DELETE` | 删除前执行 | 关联检查 |
| `AFTER DELETE` | 删除后执行 | 审计日志 |

---

### 2.4 MySQL 触发器示例

#### 自动更新时间戳

```sql
-- 创建表
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 使用触发器（MySQL 5.7 或更早版本）
DELIMITER $$
CREATE TRIGGER update_timestamp
BEFORE UPDATE ON users
FOR EACH ROW
BEGIN
    SET NEW.updated_at = CURRENT_TIMESTAMP;
END$$
DELIMITER ;
```

#### 数据验证

```sql
-- 邮箱格式验证
DELIMITER $$
CREATE TRIGGER validate_email
BEFORE INSERT ON users
FOR EACH ROW
BEGIN
    IF NEW.email NOT LIKE '%@%' THEN
        SIGNAL SQLSTATE '45000' 
        SET MESSAGE_TEXT = '邮箱格式不正确';
    END IF;
END$$
DELIMITER ;
```

#### 审计日志

```sql
-- 创建审计表
CREATE TABLE user_audit_log (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT,
    action VARCHAR(20),
    old_data JSON,
    new_data JSON,
    changed_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 插入审计
DELIMITER $$
CREATE TRIGGER audit_user_insert
AFTER INSERT ON users
FOR EACH ROW
BEGIN
    INSERT INTO user_audit_log (user_id, action, new_data)
    VALUES (NEW.id, 'INSERT', JSON_OBJECT('name', NEW.name, 'email', NEW.email));
END$$
DELIMITER ;

-- 更新审计
DELIMITER $$
CREATE TRIGGER audit_user_update
AFTER UPDATE ON users
FOR EACH ROW
BEGIN
    INSERT INTO user_audit_log (user_id, action, old_data, new_data)
    VALUES (
        NEW.id, 
        'UPDATE', 
        JSON_OBJECT('name', OLD.name, 'email', OLD.email),
        JSON_OBJECT('name', NEW.name, 'email', NEW.email)
    );
END$$
DELIMITER ;

-- 删除审计
DELIMITER $$
CREATE TRIGGER audit_user_delete
AFTER DELETE ON users
FOR EACH ROW
BEGIN
    INSERT INTO user_audit_log (user_id, action, old_data)
    VALUES (OLD.id, 'DELETE', JSON_OBJECT('name', OLD.name, 'email', OLD.email));
END$$
DELIMITER ;
```

#### 大写转换

```sql
DELIMITER $$
CREATE TRIGGER uppercase_state
BEFORE INSERT OR UPDATE ON customers
FOR EACH ROW
BEGIN
    SET NEW.state = UPPER(NEW.state);
END$$
DELIMITER ;
```

### 2.5 PostgreSQL 触发器示例

#### 自动更新时间戳

```sql
-- 创建表
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 创建触发器函数
CREATE OR REPLACE FUNCTION update_timestamp()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 创建触发器
CREATE TRIGGER update_timestamp_trigger
BEFORE UPDATE ON users
FOR EACH ROW
EXECUTE FUNCTION update_timestamp();
```

#### 数据验证

```sql
-- 邮箱格式验证
CREATE OR REPLACE FUNCTION validate_email()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.email NOT LIKE '%@%' THEN
        RAISE EXCEPTION '邮箱格式不正确';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER validate_email_trigger
BEFORE INSERT OR UPDATE ON users
FOR EACH ROW
EXECUTE FUNCTION validate_email();
```

#### 审计日志

```sql
-- 创建审计表
CREATE TABLE user_audit_log (
    id SERIAL PRIMARY KEY,
    user_id INT,
    action VARCHAR(20),
    old_data JSONB,
    new_data JSONB,
    changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 插入审计
CREATE OR REPLACE FUNCTION audit_user_insert()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO user_audit_log (user_id, action, new_data)
    VALUES (NEW.id, 'INSERT', to_jsonb(NEW));
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER audit_user_insert_trigger
AFTER INSERT ON users
FOR EACH ROW
EXECUTE FUNCTION audit_user_insert();

-- 更新审计
CREATE OR REPLACE FUNCTION audit_user_update()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO user_audit_log (user_id, action, old_data, new_data)
    VALUES (NEW.id, 'UPDATE', to_jsonb(OLD), to_jsonb(NEW));
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER audit_user_update_trigger
AFTER UPDATE ON users
FOR EACH ROW
EXECUTE FUNCTION audit_user_update();

-- 删除审计
CREATE OR REPLACE FUNCTION audit_user_delete()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO user_audit_log (user_id, action, old_data)
    VALUES (OLD.id, 'DELETE', to_jsonb(OLD));
    RETURN OLD;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER audit_user_delete_trigger
AFTER DELETE ON users
FOR EACH ROW
EXECUTE FUNCTION audit_user_delete();
```

### 2.6 触发器调试

```sql
-- MySQL 调试（使用临时表）
CREATE TEMPORARY TABLE debug_log (
    id INT AUTO_INCREMENT PRIMARY KEY,
    message VARCHAR(255),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

DELIMITER $$
CREATE TRIGGER debug_trigger
BEFORE INSERT ON users
FOR EACH ROW
BEGIN
    INSERT INTO debug_log (message) 
    VALUES (CONCAT('Inserting user: ', NEW.name));
END$$
DELIMITER ;

-- 查看调试信息
SELECT * FROM debug_log;

-- PostgreSQL 调试
CREATE OR REPLACE FUNCTION debug_function()
RETURNS TRIGGER AS $$
BEGIN
    RAISE NOTICE 'Inserting user: %', NEW.name;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER debug_trigger
BEFORE INSERT ON users
FOR EACH ROW
EXECUTE FUNCTION debug_function();
```

### 2.8 触发器性能考虑

```sql
-- ❌ 避免复杂触发器
DELIMITER $$
CREATE TRIGGER complex_trigger
AFTER INSERT ON orders
FOR EACH ROW
BEGIN
    -- 复杂的计算
    DECLARE total DECIMAL(10,2);
    
    SELECT SUM(amount) INTO total 
    FROM orders 
    WHERE user_id = NEW.user_id;
    
    -- 更新用户统计
    UPDATE users SET total_amount = total WHERE id = NEW.user_id;
    
    -- 更新部门统计
    UPDATE departments SET total_sales = total + 100;
    
    -- 记录日志
    INSERT INTO logs (...) VALUES (...);
    
    -- 发送通知（极慢）
    -- ...
END$$
DELIMITER ;

-- ✅ 优化：拆分成多个简单触发器，或使用批量处理
```

## 三、本节面试考点

| 考点 | 答案要点 |
|------|----------|
| 索引类型 | 普通、唯一、复合、全文、空间 |
| 复合索引原则 | 最左前缀原则 |
| 索引失效场景 | 函数、隐式转换、OR、LIKE通配符开头 |
| 适合建索引 | 主键、外键、WHERE、ORDER BY、JOIN |
| 不适合建索引 | 低基数列、频繁更新列 |
| 覆盖索引 | 包含查询所有列，无需回表 |
| 索引维护 | ANALYZE、OPTIMIZE、VACUUM |
| 触发器类型 | BEFORE/AFTER + INSERT/UPDATE/DELETE |
| NEW/OLD | NEW 新行，OLD 旧行 |
| 触发器用途 | 数据验证、审计日志、自动计算 |
