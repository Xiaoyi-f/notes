# SQL 学习笔记 - 高级查询与连接

## 一、JOIN 连接查询

### 1.1 连接类型对比

| 连接类型 | 说明 | 示例场景 |
|----------|------|----------|
| **INNER JOIN** | 内连接，只匹配两边都存在的记录 | 查询有订单的用户 |
| **LEFT JOIN** | 左连接，保留左表所有记录 | 查询所有用户及其订单 |
| **RIGHT JOIN** | 右连接，保留右表所有记录 | 查询所有订单及其用户 |
| **FULL OUTER JOIN** | 全连接，保留两边所有记录 | 查询所有用户和订单 |
| **CROSS JOIN** | 交叉连接，笛卡尔积 | 生成所有可能组合 |

---

### 1.2 INNER JOIN（内连接）

```sql
-- 基本语法
SELECT 列名
FROM 表A
INNER JOIN 表B ON 连接条件;

-- 示例：查询有订单的用户
SELECT u.name, o.order_id, o.order_date, o.amount
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- 等价写法（使用 WHERE）
SELECT u.name, o.order_id, o.order_date, o.amount
FROM users u, orders o
WHERE u.id = o.user_id;

-- 多表连接
SELECT u.name, p.product_name, o.order_date
FROM users u
INNER JOIN orders o ON u.id = o.user_id
INNER JOIN order_items oi ON o.order_id = oi.order_id
INNER JOIN products p ON oi.product_id = p.id;
```

**特点：**
- 只返回两边都匹配的记录
- 不匹配的记录不显示
- 最常用的连接方式

---

### 1.3 LEFT JOIN（左连接）

```sql
-- 基本语法
SELECT 列名
FROM 表A
LEFT JOIN 表B ON 连接条件;

-- 示例：查询所有用户及其订单（没有订单的用户也显示）
SELECT u.name, o.order_id, o.order_date
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

-- 注意：没有订单的用户，order_id 等字段为 NULL

-- 筛选没有订单的用户
SELECT u.name
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE o.order_id IS NULL;

-- 多表左连接
SELECT u.name, o.order_id, p.product_name
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
LEFT JOIN order_items oi ON o.order_id = oi.order_id
LEFT JOIN products p ON oi.product_id = p.id;
```

**特点：**
- 保留左表（FROM 后的表）所有记录
- 右表不匹配的字段为 NULL
- 常用于查询"有/没有"某类数据的记录

---

### 1.4 RIGHT JOIN（右连接）

```sql
-- 基本语法
SELECT 列名
FROM 表A
RIGHT JOIN 表B ON 连接条件;

-- 示例：查询所有订单及其用户（没有用户的订单也显示）
SELECT o.order_id, o.amount, u.name
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;

-- 注意：没有用户的订单，name 等字段为 NULL
```

**实际应用：**
- 很少使用，通常用 LEFT JOIN 替代
- 只需要把表的位置互换即可

```sql
-- RIGHT JOIN 可以转换为 LEFT JOIN
-- 原写法
SELECT o.order_id, u.name
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;

-- 等价写法（推荐）
SELECT o.order_id, u.name
FROM orders o
LEFT JOIN users u ON u.id = o.user_id;
```

---

### 1.5 FULL OUTER JOIN（全连接）

```sql
-- 基本语法
SELECT 列名
FROM 表A
FULL OUTER JOIN 表B ON 连接条件;

-- PostgreSQL 支持
SELECT u.name, o.order_id
FROM users u
FULL OUTER JOIN orders o ON u.id = o.user_id;

-- MySQL 不支持 FULL OUTER JOIN，需要用 UNION 模拟
SELECT u.name, o.order_id
FROM users u
LEFT JOIN orders o ON u.id = o.user_id

UNION

SELECT u.name, o.order_id
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;
```

**特点：**
- 保留两边所有记录
- 不匹配的字段为 NULL
- MySQL 不直接支持，需要 UNION 模拟

---

### 1.6 CROSS JOIN（交叉连接）

```sql
-- 基本语法
SELECT 列名
FROM 表A
CROSS JOIN 表B;

-- 等价于笛卡尔积
SELECT 列名
FROM 表A, 表B;

-- 示例：生成所有可能的组合
SELECT u.name, p.product_name
FROM users u
CROSS JOIN products p;

-- 应用场景：生成日程表、组合分析等
```

**特点：**
- 生成笛卡尔积（A × B）
- 记录数 = 表A记录数 × 表B记录数
- 通常用于特殊场景，慎用

---

### 1.7 连接表的三种方式

```sql
-- 方式一：使用 ON 子句（推荐）
SELECT u.name, o.order_id
FROM users u
JOIN orders o ON u.id = o.user_id;

-- 方式二：使用 USING 子句（列名相同时）
SELECT name, order_id
FROM users
JOIN orders USING (user_id);

-- 方式三：使用 WHERE 子句（等值连接）
SELECT u.name, o.order_id
FROM users u, orders o
WHERE u.id = o.user_id;
```

---

### 1.8 自连接

```sql
-- 自连接：把一个表当作两个表来用
-- 场景：查询员工的上级信息

SELECT 
    e.name AS employee_name,
    m.name AS manager_name
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;

-- 场景：查询同部门的所有员工
SELECT 
    e1.name AS employee1,
    e2.name AS employee2
FROM employees e1
JOIN employees e2 ON e1.department_id = e2.department_id
WHERE e1.id < e2.id;  -- 避免重复配对
```

## 二、子查询

### 2.1 子查询分类

| 类型 | 说明 | 位置 |
|------|------|------|
| **标量子查询** | 返回单行单列 | WHERE、SELECT |
| **列子查询** | 返回单列多行 | WHERE、HAVING |
| **行子查询** | 返回单行多列 | WHERE |
| **表子查询** | 返回多行多列 | FROM |

---

### 2.2 WHERE 子句中的子查询

```sql
-- 标量子查询：返回单值
-- 查询工资高于平均工资的员工
SELECT * FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);

-- 列子查询：IN、NOT IN
-- 查询有订单的用户
SELECT * FROM users
WHERE id IN (SELECT DISTINCT user_id FROM orders);

-- 查询没有订单的用户
SELECT * FROM users
WHERE id NOT IN (SELECT DISTINCT user_id FROM orders);

-- EXISTS、NOT EXISTS
-- 查询有订单的用户（比 IN 更高效）
SELECT * FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

-- 查询没有订单的用户
SELECT * FROM users u
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

-- 行子查询
-- 查询与特定员工工资和部门都相同的员工
SELECT * FROM employees
WHERE (salary, department_id) = (SELECT salary, department_id FROM employees WHERE id = 1);
```

---

### 2.3 FROM 子句中的子查询（表子查询）

```sql
-- 把子查询结果当作临时表
-- 查询每个部门工资最高的员工
SELECT e.name, e.department_id, e.salary
FROM employees e
JOIN (
    SELECT department_id, MAX(salary) AS max_salary
    FROM employees
    GROUP BY department_id
) max_sal ON e.department_id = max_sal.department_id AND e.salary = max_sal.max_salary;

-- 查询每个部门的平均工资
SELECT * FROM (
    SELECT department_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
) dept_avg
WHERE avg_salary > 5000;
```

---

### 2.4 SELECT 子句中的子查询

```sql
-- 每个用户的订单数量
SELECT 
    u.name,
    (SELECT COUNT(*) FROM orders WHERE user_id = u.id) AS order_count
FROM users u;

-- 每个商品的总销售额
SELECT 
    p.name,
    (SELECT SUM(amount) FROM order_items WHERE product_id = p.id) AS total_sales
FROM products p;
```

---

### 2.5 子查询 vs JOIN

| 特性 | 子查询 | JOIN |
|------|--------|------|
| **可读性** | 直观 | 需要理解连接 |
| **性能** | 通常较慢 | 通常较快 |
| **复杂查询** | 灵活 | 复杂时难写 |
| **MySQL优化** | 有限 | 好 |

```sql
-- 子查询方式（不推荐，MySQL 优化不好）
SELECT * FROM users
WHERE id IN (SELECT user_id FROM orders WHERE amount > 1000);

-- JOIN 方式（推荐）
SELECT DISTINCT u.* FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.amount > 1000;

-- EXISTS 方式（有时比 JOIN 快）
SELECT u.* FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id AND o.amount > 1000);
```

## 三、组合查询（UNION）

### 3.1 组合查询操作符

| 操作符 | 作用 | 是否去重 |
|--------|------|----------|
| `UNION` | 合并两个结果集 | ✅ 去重 |
| `UNION ALL` | 合并两个结果集 | ❌ 不去重 |
| `INTERSECT` | 返回交集 | ✅ 去重 |
| `EXCEPT` | 返回差集 | ✅ 去重 |

**数据库支持情况：**
| 操作符 | MySQL | PostgreSQL | Oracle | SQL Server |
|--------|-------|------------|--------|------------|
| `UNION` | ✅ | ✅ | ✅ | ✅ |
| `UNION ALL` | ✅ | ✅ | ✅ | ✅ |
| `INTERSECT` | ❌ | ✅ | ✅ | ✅ |
| `EXCEPT` | ❌ | ✅ | `MINUS` | ✅ |

---

### 3.2 UNION 和 UNION ALL

```sql
-- UNION：去重
SELECT name FROM employees_2023
UNION
SELECT name FROM employees_2024;

-- UNION ALL：不去重（更快）
SELECT name, department FROM employees_2023
UNION ALL
SELECT name, department FROM employees_2024;

-- 组合查询：把今年和去年的销售记录拼在一起
SELECT product, amount, 2023 AS year FROM sales_2023
UNION ALL
SELECT product, amount, 2024 FROM sales_2024;

-- 带排序的组合查询
(SELECT product, amount, 2023 AS year FROM sales_2023)
UNION ALL
(SELECT product, amount, 2024 FROM sales_2024)
ORDER BY amount DESC;
```

---

### 3.3 INTERSECT（交集）

```sql
-- PostgreSQL
SELECT name FROM employees_2023
INTERSECT
SELECT name FROM employees_2024;

-- MySQL 替代方案：INNER JOIN
SELECT DISTINCT e1.name
FROM employees_2023 e1
INNER JOIN employees_2024 e2 ON e1.name = e2.name;

-- MySQL 替代方案：EXISTS
SELECT DISTINCT name FROM employees_2023 e1
WHERE EXISTS (SELECT 1 FROM employees_2024 e2 WHERE e2.name = e1.name);
```

---

### 3.4 EXCEPT（差集）

```sql
-- PostgreSQL
SELECT name FROM employees_2023
EXCEPT
SELECT name FROM employees_2024;

-- MySQL 替代方案：LEFT JOIN
SELECT DISTINCT e1.name
FROM employees_2023 e1
LEFT JOIN employees_2024 e2 ON e1.name = e2.name
WHERE e2.name IS NULL;

-- MySQL 替代方案：NOT EXISTS
SELECT DISTINCT name FROM employees_2023 e1
WHERE NOT EXISTS (SELECT 1 FROM employees_2024 e2 WHERE e2.name = e1.name);
```

---

### 3.5 组合查询规则

**硬性要求：**
1. 列数相同
2. 对应列的数据类型兼容
3. 最终结果的列名以第一个 SELECT 的列名为准
4. ORDER BY 只能出现在最后

```sql
-- ✅ 正确
SELECT name, age, department FROM employees_2023
UNION
SELECT name, age, department FROM employees_2024
ORDER BY name;

-- ❌ 错误：列数不同
SELECT name, age FROM employees_2023
UNION
SELECT name FROM employees_2024;

-- ❌ 错误：ORDER BY 不能在中间
SELECT name FROM employees_2023
ORDER BY name
UNION
SELECT name FROM employees_2024;

-- ✅ 正确：使用括号改变顺序
(SELECT name FROM employees_2023 ORDER BY name)
UNION
SELECT name FROM employees_2024;
```

---

### 3.6 括号的作用

```sql
-- 混合 UNION 和 INTERSECT 时，括号决定执行顺序
-- 查询同时存在于 A 和 B，或者存在于 C 的记录
(SELECT * FROM A)
INTERSECT
(SELECT * FROM B)
UNION
(SELECT * FROM C);

-- 不同结果
SELECT * FROM A
INTERSECT
(SELECT * FROM B
UNION
SELECT * FROM C);
```

## 四、CASE 表达式

### 4.1 CASE 基本语法

```sql
-- 简单 CASE
CASE column_name
    WHEN value1 THEN result1
    WHEN value2 THEN result2
    ELSE default_result
END

-- 搜索 CASE
CASE
    WHEN condition1 THEN result1
    WHEN condition2 THEN result2
    ELSE default_result
END
```

---

### 4.2 CASE 应用示例

```sql
-- 条件分类
SELECT 
    name,
    salary,
    CASE 
        WHEN salary < 3000 THEN '低'
        WHEN salary < 6000 THEN '中'
        WHEN salary < 10000 THEN '高'
        ELSE '很高'
    END AS salary_level
FROM employees;

-- 数据转换
SELECT 
    name,
    gender,
    CASE gender
        WHEN 'M' THEN '男'
        WHEN 'F' THEN '女'
        ELSE '未知'
    END AS gender_name
FROM users;

-- 聚合统计
SELECT 
    department,
    COUNT(*) AS total,
    SUM(CASE WHEN status = 'active' THEN 1 ELSE 0 END) AS active_count,
    SUM(CASE WHEN status = 'inactive' THEN 1 ELSE 0 END) AS inactive_count
FROM employees
GROUP BY department;

-- 条件排序
SELECT name, department, salary
FROM employees
ORDER BY 
    CASE department
        WHEN 'IT' THEN 1
        WHEN 'HR' THEN 2
        ELSE 3
    END,
    salary DESC;

-- 更新数据
UPDATE products
SET price = 
    CASE 
        WHEN price < 50 THEN price * 1.1
        WHEN price < 100 THEN price * 1.05
        ELSE price * 1.02
    END
WHERE category = 'electronics';
```

## 五、常见高级查询场景

### 5.1 查询每组前N条记录

```sql
-- MySQL 8.0+ / PostgreSQL 使用窗口函数
SELECT * FROM (
    SELECT 
        department_id,
        name,
        salary,
        ROW_NUMBER() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rn
    FROM employees
) ranked
WHERE rn <= 3;

-- MySQL 5.7 使用变量
SELECT * FROM employees e
WHERE (
    SELECT COUNT(*) FROM employees e2
    WHERE e2.department_id = e.department_id AND e2.salary >= e.salary
) <= 3;
```

---

### 5.2 连续值查询

```sql
-- 查询连续登录3天的用户
WITH login_days AS (
    SELECT 
        user_id,
        login_date,
        DATE_SUB(login_date, INTERVAL ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) DAY) AS grp
    FROM user_logins
)
SELECT user_id, MIN(login_date) AS start_date, MAX(login_date) AS end_date, COUNT(*) AS days
FROM login_days
GROUP BY user_id, grp
HAVING COUNT(*) >= 3;
```

---

### 5.3 树形结构查询

```sql
-- 查询员工及其所有下属
-- MySQL 8.0+ 递归 CTE
WITH RECURSIVE employee_tree AS (
    -- 初始：选择根节点
    SELECT id, name, manager_id, 1 AS level
    FROM employees
    WHERE id = 1
    
    UNION ALL
    
    -- 递归：选择下属
    SELECT e.id, e.name, e.manager_id, et.level + 1
    FROM employees e
    JOIN employee_tree et ON e.manager_id = et.id
)
SELECT * FROM employee_tree;

-- PostgreSQL 递归查询（语法相同）
WITH RECURSIVE employee_tree AS (
    SELECT id, name, manager_id, 1 AS level
    FROM employees
    WHERE id = 1
    
    UNION ALL
    
    SELECT e.id, e.name, e.manager_id, et.level + 1
    FROM employees e
    JOIN employee_tree et ON e.manager_id = et.id
)
SELECT * FROM employee_tree;
```

## 六、窗口函数

### 6.1 什么是窗口函数

窗口函数在不改变结果集行数的情况下，对每一行进行计算。

```sql
-- 窗口函数语法
function_name() OVER (
    PARTITION BY column1, column2  -- 分组
    ORDER BY column3                -- 排序
    frame_clause                    -- 窗口范围
)
```

---

### 6.2 常用窗口函数

| 函数类型 | 函数 | 说明 |
|----------|------|------|
| **排名函数** | `ROW_NUMBER()` | 顺序排名（1,2,3,4） |
| | `RANK()` | 跳跃排名（1,2,2,4） |
| | `DENSE_RANK()` | 密集排名（1,2,2,3） |
| **偏移函数** | `LAG()` | 获取前一行 |
| | `LEAD()` | 获取后一行 |
| | `FIRST_VALUE()` | 窗口内第一个值 |
| | `LAST_VALUE()` | 窗口内最后一个值 |
| **聚合函数** | `SUM()` | 累计和 |
| | `AVG()` | 移动平均 |
| | `COUNT()` | 累计计数 |

---

### 6.3 窗口函数示例

```sql
-- ROW_NUMBER：顺序排名
SELECT 
    name,
    department_id,
    salary,
    ROW_NUMBER() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rank
FROM employees;

-- RANK：跳跃排名（相同名次后跳过）
SELECT 
    name,
    department_id,
    salary,
    RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rank
FROM employees;
-- 结果：1,2,2,4,5（两个第2名后，下一个是第4名）

-- DENSE_RANK：密集排名（相同名次不跳过）
SELECT 
    name,
    department_id,
    salary,
    DENSE_RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rank
FROM employees;
-- 结果：1,2,2,3,4（两个第2名后，下一个是第3名）

-- LAG：获取前一行
SELECT 
    name,
    salary,
    LAG(salary, 1) OVER (ORDER BY id) AS prev_salary,
    salary - LAG(salary, 1) OVER (ORDER BY id) AS salary_diff
FROM employees;

-- LEAD：获取后一行
SELECT 
    name,
    salary,
    LEAD(salary, 1) OVER (ORDER BY id) AS next_salary
FROM employees;

-- 累计求和
SELECT 
    order_date,
    amount,
    SUM(amount) OVER (ORDER BY order_date) AS cumulative_sum
FROM orders;

-- 移动平均
SELECT 
    order_date,
    amount,
    AVG(amount) OVER (
        ORDER BY order_date
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS moving_avg
FROM orders;
```

## 七、连接 vs 组合查询

| 特性 | JOIN（连接） | UNION（组合） |
|------|-------------|---------------|
| **作用** | 左右拼接数据 | 上下拼接数据 |
| **列数** | 相同或不同 | 必须相同 |
| **数据源** | 不同表 | 相同或类似结构 |
| **结果行数** | 通常是相乘关系 | 相加关系 |
| **去重** | 不去重 | UNION去重 |
| **典型场景** | 关联查询 | 合并查询结果 |

```sql
-- 连接查询：把产品表和订单表左右拼在一起查产品详情
SELECT * FROM orders LEFT JOIN products ON orders.product_id = products.id;

-- 组合查询：把今年和去年的销售记录上下拼在一起
SELECT product, amount, 2023 AS year FROM sales_2023
UNION ALL
SELECT product, amount, 2024 FROM sales_2024;
```

## 本节面试考点

| 考点 | 答案要点 |
|------|----------|
| JOIN类型 | INNER JOIN、LEFT JOIN、RIGHT JOIN、FULL OUTER JOIN、CROSS JOIN |
| LEFT JOIN特点 | 保留左表所有记录，右表不匹配为NULL |
| 自连接场景 | 查询层级结构、同表关联 |
| 子查询类型 | 标量、列、行、表子查询 |
| EXISTS vs IN | EXISTS更高效，子查询结果多时明显 |
| UNION vs UNION ALL | UNION去重（慢），UNION ALL不去重（快） |
| MySQL不支持 | INTERSECT、EXCEPT |
| 窗口函数语法 | function() OVER (PARTITION BY ... ORDER BY ...) |
| RANK vs DENSE_RANK | RANK跳跃排名，DENSE_RANK密集排名 |
| LAG/LEAD | 获取前一行/后一行 |
