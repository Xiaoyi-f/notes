### 3. 串口工具高级用法

```
HEX显示模式：
  设备发的是二进制：AA 55 0C 01 ...
  文本模式会显示乱码
  HEX模式正确显示：AA 55 0C 01 01 09 F6 ...

时间戳功能：
  开启后每条数据前加时间
  用于分析设备上报频率
  用于排查时序问题

多字符串发送：
  预定义多条命令，一键发送
  例：定义F1=LED_ON, F2=LED_OFF
```

### 3. 命令行工具 mosquitto_pub/sub

```bash
# 安装
sudo apt install mosquitto-clients

# 订阅
mosquitto_sub -h broker.emqx.io -t "home/001/temperature" -v

# 发布
mosquitto_pub -h broker.emqx.io -t "home/001/light/cmd" -m '{"action":"on"}'

# 带用户名密码
mosquitto_sub -h broker.emqx.io -u admin -P password -t "#"
```

## 三、网络抓包工具——Wireshark

```
Wireshark 可以"看到"网线上传输的所有数据。

场景1：MQTT连接不上
  → Wireshark抓包看 TCP三次握手是否成功
  → 看 MQTT CONNECT 包是否被服务器拒绝

场景2：数据异常
  → 抓包看原始 MQTT PUBLISH 内容
  → 确认是设备发错了还是云端解析错了

使用方法：
1. 选择网卡（WiFi或有线）
2. 设置过滤：mqtt 或 tcp.port == 1883
3. 开始抓包
4. 找到对应的报文，右键 → Follow → TCP Stream
```

## 四、逻辑分析仪

### 什么时候用？

```
UART通信异常，不确定是发送端还是接收端的问题：

┌─────────────────────────────────────────┐
│         逻辑分析仪（如 Saleae）          │
│                                         │
│  CH0 ─────► 接设备A的TX                  │
│  CH1 ─────► 接设备B的RX                  │
│  GND ─────► 共地                         │
│                                         │
│  软件显示实际波形：                        │
│                                         │
│  CH0 ┌──┐  ┌──┐  ┌──┐  ← 设备A确实发了   │
│      │  │  │  │  │  │                    │
│      └──┘  └──┘  └──┘                    │
│  CH1 ┌──┐  ┌──┐  ┌──┐  ← 设备B收到了     │
│      │  │  │  │  │  │                    │
│      └──┘  └──┘  └──┘                    │
│                                         │
│  可以精确测量：                           │
│  - 每个bit的持续时间（验证波特率）         │
│  - 起始位/停止位是否正确                  │
│  - 有没有数据丢失                         │
└─────────────────────────────────────────┘

推荐：Saleae Logic（正版$500+，山寨版¥100+）
      或者 DSLogic（开源，¥300+）
```

## 五、示波器

```
示波器看的是"模拟信号"的电压变化：

场景1：UART没有共地
  → 示波器看到信号电平不对
  → 电压在0-3.3V之间跳变才对

场景2：GPIO输出不稳定
  → 看到电压有毛刺
  → 可能需要加滤波电容

场景3：电源纹波太大
  → 3.3V电源上有高频噪声
  → 影响ADC精度

入门级：DSO138（¥100+，够看UART）
进阶级：Rigol DS1054Z（¥2000+）
```

## 六、调试工具速查表

| 问题现象 | 用什么工具 | 看什么 |
|---------|-----------|--------|
| 串口没数据 | 串口助手 | 波特率/端口对不对 |
| 串口数据乱码 | 串口助手+逻辑分析仪 | 波特率不匹配/信号质量 |
| MQTT连不上 | MQTTX+Wireshark | 连接参数/网络连通性 |
| MQTT消息丢失 | MQTTX | QoS级别/Retained设置 |
| 数据解析错误 | 串口助手HEX模式 | 原始字节 vs 解析结果 |
| 时序不对 | 逻辑分析仪 | 波形时序 |
| 信号质量差 | 示波器 | 电压幅度/噪声 |
| 设备频繁掉线 | Wireshark | TCP连接状态 |
| OTA下载失败 | 串口助手 | 下载进度/错误码 |

## 七、调试方法论

```
遇到问题时，按这个顺序排查：

1. 物理层（线有没有接对）
   → 万用表测电压
   → 逻辑分析仪看波形
   → 确认TX/RX没有接反

2. 协议层（参数对不对）
   → 波特率/数据位/停止位/校验
   → MQTT地址/端口/用户名密码
   → Topic格式是否正确

3. 数据层（内容对不对）
   → HEX模式看原始数据
   → 对照协议文档逐字节核对
   → 计算校验和验证

4. 应用层（逻辑对不对）
   → 断点调试代码
   → 加日志打印中间状态
   → 最小化复现问题
```
