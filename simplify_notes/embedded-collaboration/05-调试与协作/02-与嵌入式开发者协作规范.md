## 二、通信协议文档模板（必写！）

```markdown
# XX项目通信协议 V1.0

## 1. 基本信息
| 项目 | 内容 |
|------|------|
| 协议版本 | V1.0 |
| 生效日期 | 2024-01-15 |
| 适用设备 | 温湿度传感器V2 |
| 通信方式 | UART / MQTT |

## 2. 物理层
### 2.1 UART参数
- 波特率：115200
- 数据位：8
- 停止位：1
- 校验位：None
- 流控：None

### 2.2 MQTT参数（如用MQTT）
- Broker地址：xxx
- 端口：1883/8883
- Topic前缀：device/{deviceId}/
- 客户端ID格式：device_{deviceId}_{random}

## 3. 帧格式
| 字段 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| 帧头 | 0 | 2 | 固定0xAA 0x55 |
| 长度 | 2 | 1 | 总长度 |
| 命令 | 3 | 1 | 见命令表 |
| 设备ID | 4 | 1 | 1-255 |
| 数据 | 5 | N | 根据命令 |
| 校验 | 5+N | 1 | XOR |

## 4. 命令定义
| 命令码 | 名称 | 方向 | 数据长度 | 数据格式 | 说明 |
|--------|------|------|---------|---------|------|
| 0x01 | 上报温湿度 | 设备→云端 | 6 | 温度(2B)+湿度(4B) | 每5秒上报 |
| 0x02 | 心跳 | 设备→云端 | 0 | 无 | 每30秒 |
| 0x81 | 控制LED | 云端→设备 | 1 | 亮度(1B) | 0-255 |

## 5. 数据解析
### 5.1 温度（命令0x01）
```
原始值 = (高字节 << 8) | 低字节
温度(°C) = 原始值 / 100.0
示例：0x09F6 = 2550 → 25.50°C
```

### 5.2 湿度（命令0x01）
```
原始值 = 4字节大端整数
湿度(%) = 原始值 / 100.0
示例：0x00001770 = 6000 → 60.00%
```

## 6. 错误处理
| 错误码 | 说明 | 处理 |
|--------|------|------|
| 0xE1 | 校验失败 | 丢弃该帧 |
| 0xE2 | 命令不支持 | 返回错误帧 |
| 0xE3 | 参数错误 | 返回错误帧 |
| 0xE4 | 执行失败 | 返回错误帧 |

## 7. 时序要求
- 命令响应时间：< 100ms
- 心跳间隔：30s
- 心跳超时：90s
- 重连间隔：5s, 10s, 20s, 60s（指数退避）

## 8. 版本历史
| 版本 | 日期 | 修改人 | 修改内容 |
|------|------|--------|---------|
| V1.0 | 2024-01-15 | 张三/李四 | 初始版本 |
```

## 三、协作中的常见问题和避免方法

### 问题1：大小端不一致

```
❌ 你默认小端，嵌入式默认大端

你发送：0x1234
  内存中：34 12（小端）

嵌入式读取：
  高字节=0x34，低字节=0x12
  解析结果：0x3412（完全错了！）

✅ 解决方法：
  1. 协议文档明确规定大端/小端
  2. 双方在代码里用 htons/ntohs 转换
  3. 联调时先用0x1234这种特殊值验证
```

### 问题2：数据类型精度

```
❌ 协议里写"温度用float传"

问题：
  - 嵌入式端：用IEEE 754 float（4字节）
  - 你解析：也是IEEE 754 float
  - 看起来没问题...

但：
  - 有些MCU不支持硬件浮点，用软件模拟
  - 精度可能有微小差异
  - 25.5 变成 25.499998

✅ 解决方法：
  用定点数代替浮点数
  协议："温度放大100倍用uint16传"
  嵌入式：temp * 100 → 发送
  你：收到 / 100.0 → 显示
```

### 问题3：字符串编码

```
❌ 设备发中文，显示乱码

设备发："温度正常"（GBK编码）
你解析：UTF-8 → 乱码！

✅ 解决方法：
  协议明确规定：所有字符串用UTF-8
  或：不用字符串，用命令码代替
  0x01 = "温度正常"
  0x02 = "温度过高"
```

### 问题4：时序问题

```
❌ 你发命令太快，设备处理不过来

你：连续发10条命令
设备：串口接收缓冲区只有64字节
      第3条开始就丢了

✅ 解决方法：
  1. 等收到响应再发下一条
  2. 或：设备回复ACK后再发
  3. 协议里规定最小间隔（如100ms）
```

## 四、协作沟通 checklist

```
每次联调前，双方确认：

□ 协议文档版本一致（都在看V1.0）
□ 物理连接正确（TX/RX没接反，共地）
□ 通信参数一致（波特率、MQTT地址等）
□ 测试数据准备好（已知输入和期望输出）
□ 调试工具就位（串口助手/MQTTX打开）

发现问题时：

□ 抓原始数据（HEX模式）
□ 对照协议文档逐字节核对
□ 先确认是发送方问题还是接收方问题
□ 修改后更新协议文档
□ 记录问题和解决方法
```
