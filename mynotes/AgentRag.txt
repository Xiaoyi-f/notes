## 智能体 
在人工智能领域，智能体被定义为任何能够通过传感器（Sensors）感知其所处环境（Environment），并自主地通过执行器（Actuators）采取行动（Action）以达成特定目标的实体
分类: 
基于内部决策架构的智能体
基于时间与反应性的智能体: 反应式智能体、规划式智能体、混合式智能体
基于知识表示的分类: 符号主义、亚符号主义、神经符号主义

### 智能体的构成与运行原理 
使用PEAS(Performance, Environment, Actuators, Sensors)描述"任务环境"

智能体循环(Agent Loop)
感知 (Perception): 这是循环的起点。智能体通过其传感器（例如，API 的监听端口、用户输入接口）接收来自环境的输入信息。这些信息，即观察 (Observation)，既可以是用户的初始指令，也可以是上一步行动所导致的环境状态变化反馈
思考 (Thought): 接收到观察信息后，智能体进入其核心决策阶段。对于 LLM 智能体而言，这通常是由大语言模型驱动的内部推理过程。如图所示，“思考”阶段可进一步细分为两个关键环节:
规划 (Planning): 智能体基于当前的观察和其内部记忆，更新对任务和环境的理解，并制定或调整一个行动计划。这可能涉及将复杂目标分解为一系列更具体的子任务
工具选择 (Tool Selection): 根据当前计划，智能体从其可用的工具库中，选择最适合执行下一步骤的工具，并确定调用该工具所需的具体参数
行动 (Action): 决策完成后，智能体通过其执行器（Actuators）执行具体的行动。这通常表现为调用一个选定的工具（如代码解释器、搜索引擎 API），从而对环境施加影响，意图改变环境的状态

简单智能体的构建流程:
1. 写好可以使用的工具函数
2. 建立提示词与要求模块
3. 接入大模型,合成提示词,请求大模型
4. 正则解析大模型返回结果,条件匹配调用工具
5. 执行行动循环

### Transformer架构解析
Transformer架构由谷歌团队提出,为了解决Agent循环实现模式的弱并行能力的问题,Transformer抛弃循环形式,转而完全依赖一种名为"注意力(Attention)"的机制来捕捉序列内依赖关系
多头注意力机制: 把一次做完变成分成几组，分开做，再合并

### Decoder-Only 架构 
特点: 自回归
给模型一个起始文本（例如 “Datawhale Agent is”）
模型预测出下一个最有可能的词（例如 “a”）
模型将自己刚刚生成的词 “a” 添加到输入文本的末尾，形成新的输入（“Datawhale Agent is a”）
模型基于这个新输入，再次预测下一个词（例如 “powerful”）
不断重复这个过程，直到生成完整的句子或达到停止条件

优势: 
训练目标统一：模型的唯一任务就是“预测下一个词”，这个简单的目标非常适合在海量的无标注文本数据上进行预训练
结构简单，易于扩展：更少的组件意味着更容易进行规模化扩展。今天的 GPT-4、Llama 等拥有数千亿甚至万亿参数的巨型模型，都是基于这种简洁的架构
天然适合生成任务：其自回归的工作模式与所有生成式任务（对话、写作、代码生成等）完美契合，这也是它能成为构建通用智能体基础的核心原因

### 与大语言模型交互 
提示词工程: 提示大模型输出我们的预期结果 
1) Temperature: 概率分布的采样策略
    0 <= temperature < 0.3 输出更加精准 严谨事务
    0.3 <= temperature < 0.7 输出自然 日常
    0.7 <= temperature < 2 输出发散/创新 艺术灵感/启发 
2) Top-k: 概率从高到低排序,取排名前k个的token组成"候选集"
3) Top-p: 概率从高到低排序,取概率和为p的token组成"候选集"
4) 样本模式: 零样本提示、单样本提示、少样本提示(Few-Shot)
5) 指令调优: 对指令进行特定描述
6) 角色扮演: 赋予模型一个特定角色,我们可以引导他的回答风格、语气和知识范围等
7) 上下文示例: 类似样本模式,举出一些上下文对答样本 
8) 思维链: 对于需要多步骤思考的场景,直接让模型给答案容易出错,思维链引导模型一步步思考,提升推理能力 

文本分词: 将文本转化出词元,然后底层进行向量表示与概率推理
分词模式: 按词分词 按字符分词 

缩放法则（Scaling Laws）: 揭示了模型性能与模型参数量、训练数据量以及计算资源之间存在着可预测的幂律关系。这一发现为大语言模型的持续发展提供了理论指导，阐明了增加资源投入能够系统性提升模型性能的底层逻辑
模型幻觉（Hallucination）通常指的是大语言模型生成的内容与客观事实、用户输入或上下文信息相矛盾，或者生成了不存在的事实、实体或事件
幻觉的本质是模型在生成过程中，过度自信地“编造”了信息，而非准确地检索或推理

### 智能体经典范式构建 -- 主要靠工作流实现
经典范式 - 思行相辅 先思后行 反思优化
ReAct (Reasoning and Acting): 一种将“思考”和“行动”紧密结合的范式，让智能体边想边做，动态调整
Plan-and-Solve: 一种“三思而后行”的范式，智能体首先生成一个完整的行动计划，然后严格执行
Reflection: 一种赋予智能体“反思”能力的范式，通过自我批判和修正来优化结果

建议
规划层: Plan-and-Execute 
工具层: 异常机制 Human-in-the-loop 
记忆层: 短期记忆维持当前对话 向量数据库/Postgre+pgvector实现长期记忆 提取并且存储用户画像
状态与评估层: 防止死循环 设置最大迭代次数(Max Steps) 卡死触发降级方案 Human-in-the-loop

from langchain.tools import tool 
@tool
def get_weather(location):

from langchain.agents import create_agent

for chunk in stream:
    print(chunk.content, end="", flush=True)
