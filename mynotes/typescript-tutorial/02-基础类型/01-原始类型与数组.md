# 01 - 原始类型与数组

---

## 一、原始类型（Primitive Types）

TypeScript 在 JavaScript 原始类型的基础上，给每个类型加了类型标注。

```typescript
// ── string 字符串 ──
let userName: string = "张三"
userName = "李四"           // ✅ 正确
// userName = 123           // ❌ 错误：不能把 number 赋给 string

// ── number 数字 ──
let age: number = 25
let price: number = 99.99
let hex: number = 0xff      // 十六进制
let binary: number = 0b1010 // 二进制

age = "25"                  // ❌ 错误

// ── boolean 布尔 ──
let isVIP: boolean = true
let isActive: boolean = false

// ── bigint 大整数 ──
let bigNum: bigint = 9007199254740991n

// ── symbol 符号 ──
let sym: symbol = Symbol("key")
```

**为什么要标注类型？**

```javascript
// 没标注时，IDE 不知道 price 是什么
let price = getPriceFromServer()  // 你也不知道返回的是什么
price.  // 按 . 之后没有任何提示

// 标了类型，IDE 就知道 price 是 number
let price: number = getPriceFromServer()
price.  // IDE 提示: toFixed, toString, toPrecision...
price.toFixed(2)  // ✅ 确定 number 有这个 API
```

## 二、特殊类型

### null 和 undefined

```typescript
// TypeScript 中，null 和 undefined 是独立的类型
let emptyValue: null = null
let notDefined: undefined = undefined

// strictNullChecks 开启时：
let name: string = "张三"
name = null        // ❌ 错误：string 不能是 null

// 如果要允许 null，需要用联合类型
let maybeName: string | null = "张三"
maybeName = null   // ✅ 正确
maybeName = "李四" // ✅ 正确
```

**为什么区分 null 和 undefined？**

这是 TS 帮你避免的一个经典 Bug：

```javascript
// JavaScript
function getLength(str) {
  return str.length   // 如果 str 是 null，这里就报错
}

getLength(null)  // ❌ 运行时错误：Cannot read property 'length' of null
```

```typescript
// TypeScript
function getLength(str: string): number {
  return str.length
}

getLength(null)  // ❌ 编译错误：参数不能是 null

// 如果你确实可能传 null，要显式声明
function getLengthSafe(str: string | null): number {
  // TS 强制你处理 null 的情况
  if (str === null) {
    return 0
  }
  return str.length   // ✅ 这里 TS 知道 str 肯定不是 null
}
```

### any（任意类型）

```typescript
// any 表示"任何类型"，相当于关闭了类型检查
let anything: any = "hello"
anything = 42        // ✅
anything = true      // ✅
anything.foo()       // ✅ TS 不会报错（但运行时可能报错）

// 什么时候用 any？
// 1. 从 JS 迁移到 TS 的过渡期
// 2. 第三方库没有类型定义
// 3. 临时调试

// ⚠️ 不要滥用 any！用多了就等于没写 TypeScript
```

---

### unknown（未知类型）

```typescript
// unknown 也是"任何类型"，但比 any 更安全
let input: unknown = "hello"

// unknown 类型的变量不能直接用，必须先判断或断言
console.log(input.length)   // ❌ 错误：unknown 没有 length 属性

// ✅ 先判断类型
if (typeof input === "string") {
  console.log(input.length) // ✅ TS 知道这里 input 是 string
}

// ✅ 或者用类型断言
console.log((input as string).length)
```

**any vs unknown 对比**：

| | any | unknown |
|--|-----|---------|
| 能接收任何值 | ✅ | ✅ |
| 能调用任何方法 | ✅ | ❌ 必须先判断类型 |
| 安全性 | 低（可能运行时出错） | 高（强制类型检查） |
| 推荐用法 | 避免使用 | 不确定类型时优先用 |

```typescript
// 最佳实践：优先用 unknown，避免用 any
function parseJSON(jsonString: string): unknown {
  return JSON.parse(jsonString)  // 返回 unknown，调用方必须判断类型
}

const data = parseJSON('{"name": "张三"}')
// data.name  // ❌ 报错，必须判断
if (typeof data === "object" && data !== null && "name" in data) {
  console.log(data.name)  // ✅
}
```

### never（永不存在的类型）

```typescript
// never 表示"永远不会发生的值"
// 什么情况下会用到？

// 场景1：函数永远抛出异常，不会正常返回
function throwError(message: string): never {
  throw new Error(message)
}

// 场景2：死循环，永远不会结束
function infiniteLoop(): never {
  while (true) {
    // 永远执行...
  }
}

// 场景3：switch 的 exhaustive check（穷尽检查）
type Shape = "circle" | "square" | "triangle"

function getArea(shape: Shape): number {
  switch (shape) {
    case "circle": return 3.14
    case "square": return 4
    case "triangle": return 3
    default:
      // 如果以后 Shape 加了新类型，这里会报错
      // 因为 shape 的剩余类型是 never，不能赋值给 never
      const _exhaustiveCheck: never = shape
      return _exhaustiveCheck
  }
}
```

## 三、数组类型

```typescript
// 方式一：类型 + 方括号
let numbers: number[] = [1, 2, 3]
let names: string[] = ["张三", "李四", "王五"]

numbers.push(4)        // ✅
numbers.push("5")      // ❌ 不能 push string

// 方式二：泛型写法（等价）
let numbers2: Array<number> = [1, 2, 3]
let names2: Array<string> = ["张三", "李四"]

// 多维数组
let matrix: number[][] = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9]
]

// 混合类型数组
let mixed: (string | number)[] = ["张三", 25, "李四", 30]
```

**数组的类型有什么用？**

```typescript
// 定义用户信息列表
interface User {
  id: number
  name: string
  age: number
}

let users: User[] = [
  { id: 1, name: "张三", age: 25 },
  { id: 2, name: "李四", age: 30 }
]

// 遍历时有完整提示
users.forEach(user => {
  console.log(user.name)  // IDE 提示 name, id, age
  console.log(user.nmae)  // ❌ 报错：拼写错误
})

// map 有返回值类型推断
const names = users.map(user => user.name)
// names 的类型自动推断为 string[]
```

## 四、元组（Tuple）

元组是**固定长度、固定类型**的数组。

```typescript
// 表示一个坐标点：[x, y]
let point: [number, number] = [10, 20]
point = [30, 40]        // ✅
point = [10]            // ❌ 长度不对
point = [10, "20"]      // ❌ 类型不对

// 应用场景：RGB 颜色 [红, 绿, 蓝]
let color: [number, number, number] = [255, 128, 0]

// 应用场景：HTTP 状态码和描述
let response: [number, string] = [200, "OK"]

// 应用场景：Map 的键值对
let entry: [string, number] = ["age", 25]

// 可以设置可选元素
let profile: [string, number, string?] = ["张三", 25]
profile = ["李四", 30, "工程师"]  // ✅ 第三个可选
```

**元组 vs 数组的区别**：

| | 数组 `number[]` | 元组 `[number, string]` |
|--|----------------|------------------------|
| 长度 | 不固定 | 固定 |
| 元素类型 | 全部相同 | 可以不同 |
| 用途 | 同类数据的集合 | 有固定结构的数据 |

```typescript
// 错误示例：用数组代替元组
let userInfo: (string | number)[] = ["张三", 25, "北京"]
// 问题：不知道哪个位置是什么含义

// 正确做法：用元组或对象
let userInfo2: [string, number, string] = ["张三", 25, "北京"]
// 更好：用对象（语义更清晰）
let userInfo3 = { name: "张三", age: 25, city: "北京" }
```

## 五、类型推断

TypeScript 会自动推断类型，你**不一定**需要每个地方都写类型标注。

```typescript
// TypeScript 会自动推断类型
let name = "张三"        // 推断为 string
let age = 25             // 推断为 number
let isActive = true      // 推断为 boolean

// 数组的类型推断
let numbers = [1, 2, 3]           // 推断为 number[]
let mixed = [1, "hello", true]    // 推断为 (number | string | boolean)[]

// 函数返回值的类型推断
function add(a: number, b: number) {
  return a + b    // 推断返回 number
}

// 什么时候需要显式标注？
// 1. 变量初始值不能推断出正确类型时
let userInput: string | number = getUserInput()

// 2. 函数返回值比较复杂时
function getUser(): { id: number; name: string } {
  return { id: 1, name: "张三" }
}

// 3. 你期望的类型和推断的不一致时
let items: (string | null)[] = ["a", null, "b"]
// 如果不标注，推断为 (string | null)[]，结果一样
// 但如果初始只有 ["a", "b"]，会推断为 string[]，以后 push null 就报错
```
