   🎯 工作必考题

  Q1: == 和 equals 的区别？

  // == 比较的是内存地址（基本类型比较值）
  String s1 = new String("abc");
  String s2 = new String("abc");
  s1 == s2;      // false（不同对象）
  s1.equals(s2); // true（内容相同）

  // 基本类型
  int a = 5;
  int b = 5;
  a == b;  // true（值相同）

  Q2: static 关键字的用法？

  public class Test {
      static int count = 0;           // 静态变量，所有实例共享
      public static void method() {}  // 静态方法，通过类名调用
      static {                        // 静态代码块，类加载时执行
          System.out.println("静态代码块");
      }
  }
  Test.method();  // 类名直接调用

  Q3: final 关键字的用法？

  final class A {}           // 类不能被继承
  class B {
      final void method() {} // 方法不能被重写
      final int AGE = 18;    // 常量，值不能修改
  }

  Q4: volatile 的作用？

  // 1. 保证可见性：一个线程修改，其他线程立即可见
  // 2. 禁止指令重排
  // 3. 不保证原子性（如 i++ 需要配合 synchronized）
  private volatile boolean flag = true;

  Q5: transient 的作用？

  // 序列化时忽略该字段，不会被保存到文件/网络
  public class User implements Serializable {
      private String name;
      private transient String password;  // 不序列化密码
  }

  等待唤醒机制（详解）

  核心概念

  等待唤醒机制是多线程间通信的一种方式，让线程可以：
  - 在某个条件不满足时等待（释放锁，进入等待状态）
  - 在条件满足后被其他线程唤醒（重新获取锁，继续执行）

  基本方法（Object 类）

  import java.lang.*;

  // 这些方法必须在同步代码块或同步方法中使用，且必须用同一个锁对象调用
  obj.wait();          // 当前线程等待，释放锁对象
  obj.wait(long timeout);  // 等待指定毫秒数，超时自动唤醒
  obj.notify();        // 随机唤醒一个等待该锁对象的线程
  obj.notifyAll();     // 唤醒所有等待该锁对象的线程

  为什么必须在同步中使用？

  // 错误示例 - 会抛出 IllegalMonitorStateException
  Object lock = new Object();
  lock.wait();  // ❌ 没有获取锁就调用 wait()

  // 正确示例
  synchronized (lock) {
      lock.wait();  // ✅ 已获取锁，可以调用
  }

  原因：wait() 需要释放当前线程持有的锁，如果没有持有锁就无法释放，所以 Java 强制要求必须在同步代码中使用。

  生产者消费者模式（经典案例）

  import java.util.LinkedList;
  import java.util.Queue;

  public class ProducerConsumer {
      // 共享数据容器
      private static final Queue<String> queue = new LinkedList<>();
      private static final int MAX_SIZE = 5;
      private static final Object LOCK = new Object(); // 必须是同一个锁对象

      public static void main(String[] args) {
          // 生产者线程
          Thread producer = new Thread(() -> {
              for (int i = 1; i <= 20; i++) {
                  synchronized (LOCK) {
                      // 如果队列满了，生产者等待
                      while (queue.size() >= MAX_SIZE) {
                          try {
                              System.out.println("队列已满，生产者等待...");
                              LOCK.wait();  // 释放锁，进入等待状态
                          } catch (InterruptedException e) {
                              e.printStackTrace();
                          }
                      }

                      // 生产产品
                      String product = "产品" + i;
                      queue.offer(product);
                      System.out.println("生产: " + product + "，当前数量: " + queue.size());

                      // 唤醒消费者
                      LOCK.notifyAll();  // 唤醒所有等待该锁的线程
                  }

                  try {
                      Thread.sleep(100);  // 模拟生产耗时
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
              }
          }, "生产者");

          // 消费者线程
          Thread consumer = new Thread(() -> {
              while (true) {
                  synchronized (LOCK) {
                      // 如果队列空了，消费者等待
                      while (queue.isEmpty()) {
                          try {
                              System.out.println("队列为空，消费者等待...");
                              LOCK.wait();  // 释放锁，进入等待状态
                          } catch (InterruptedException e) {
                              e.printStackTrace();
                          }
                      }

                      // 消费产品
                      String product = queue.poll();
                      System.out.println("消费: " + product + "，当前数量: " + queue.size());

                      // 唤醒生产者
                      LOCK.notifyAll();  // 唤醒所有等待该锁的线程
                  }

                  try {
                      Thread.sleep(200);  // 模拟消费耗时
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
              }
          }, "消费者");

          producer.start();
          consumer.start();
      }
  }

  为什么用 while 而不是 if？

  // ❌ 错误写法 - 使用 if
  synchronized (LOCK) {
      if (queue.isEmpty()) {
          LOCK.wait();  // 被唤醒后不会重新检查条件
      }
      // 如果被虚假唤醒（spurious wakeup），可能执行到此处时队列仍是空的
      String product = queue.poll();  // 可能返回 null！
  }

  // ✅ 正确写法 - 使用 while
  synchronized (LOCK) {
      while (queue.isEmpty()) {  // 被唤醒后会重新检查条件
          LOCK.wait();
      }
      // 保证队列一定有元素
      String product = queue.poll();
  }

  原因：wait() 可能被虚假唤醒（spurious wakeup），操作系统可能会在没有 notify 的情况下唤醒线程。使用 while 循环可以确保被唤醒后重新检查条件是否满足。

  wait() 与 sleep() 的区别

  // sleep() - Thread 类的静态方法
  Thread.sleep(1000);
  // 1. 不释放锁（如果在同步代码块中）
  // 2. 必须传入时间，不能被 notify 唤醒
  // 3. 时间到自动唤醒

  // wait() - Object 类的实例方法
  synchronized (obj) {
      obj.wait();           // 等待直到被 notify
      obj.wait(1000);       // 等待最多 1000 毫秒
  }
  // 1. 会释放锁
  // 2. 必须在同步代码中用同一个锁对象调用
  // 3. 可以被 notify / notifyAll 唤醒，也可以超时自动唤醒

  // 演示区别
  public class WaitSleepDemo {
      private static final Object LOCK = new Object();

      public static void main(String[] args) {
          // sleep 不释放锁
          Thread t1 = new Thread(() -> {
              synchronized (LOCK) {
                  System.out.println("Thread1 获取锁，开始 sleep");
                  try {
                      Thread.sleep(2000);  // sleep 期间持有锁
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
                  System.out.println("Thread1 sleep 结束，释放锁");
              }
          });

          // wait 释放锁
          Thread t2 = new Thread(() -> {
              try {
                  Thread.sleep(100);  // 让 t1 先执行
              } catch (InterruptedException e) {
                  e.printStackTrace();
              }
              synchronized (LOCK) {
                  System.out.println("Thread2 获取锁，开始 wait");
                  try {
                      LOCK.wait();  // wait 期间释放锁
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
                  System.out.println("Thread2 被唤醒");
              }
          });

          Thread t3 = new Thread(() -> {
              try {
                  Thread.sleep(1500);  // 等待合适时机
              } catch (InterruptedException e) {
                  e.printStackTrace();
              }
              synchronized (LOCK) {
                  System.out.println("Thread3 获取锁，唤醒 t2");
                  LOCK.notifyAll();
              }
          });

          t1.start();
          t2.start();
          t3.start();
      }
  }

  Condition 接口（Lock 的等待唤醒机制）

  import java.util.concurrent.locks.*;

  public class ConditionDemo {
      private static final Lock lock = new ReentrantLock();
      private static final Condition notFull = lock.newCondition();  // 生产者等待条件
      private static final Condition notEmpty = lock.newCondition(); // 消费者等待条件

      private static final Queue<String> queue = new LinkedList<>();
      private static final int MAX_SIZE = 5;

      public static void main(String[] args) {
          Thread producer = new Thread(() -> {
              for (int i = 1; i <= 20; i++) {
                  lock.lock();
                  try {
                      while (queue.size() >= MAX_SIZE) {
                          System.out.println("队列已满，生产者等待...");
                          notFull.await();  // 类似 wait()，但会释放 lock
                      }

                      String product = "产品" + i;
                      queue.offer(product);
                      System.out.println("生产: " + product + "，当前数量: " + queue.size());

                      notEmpty.signal();  // 唤醒消费者（类似 notify）
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  } finally {
                      lock.unlock();
                  }

                  try {
                      Thread.sleep(100);
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
              }
          }, "生产者");

          Thread consumer = new Thread(() -> {
              while (true) {
                  lock.lock();
                  try {
                      while (queue.isEmpty()) {
                          System.out.println("队列为空，消费者等待...");
                          notEmpty.await();
                      }

                      String product = queue.poll();
                      System.out.println("消费: " + product + "，当前数量: " + queue.size());

                      notFull.signal();  // 唤醒生产者
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  } finally {
                      lock.unlock();
                  }

                  try {
                      Thread.sleep(200);
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
              }
          }, "消费者");

          producer.start();
          consumer.start();
      }
  }

  Condition 与 Object wait/notify 的优势

  // Object wait/notify 的限制
  // 1. 只能有一个等待队列（所有等待同一锁的线程都在一个队列）
  // 2. notify() 随机唤醒一个，不能精确唤醒特定类型的线程
  // 3. 不支持超时等待（需要用 wait(long timeout)）

  // Condition 的优势
  // 1. 可以创建多个 Condition，实现精确唤醒
  // 2. 支持超时等待 await(long time, TimeUnit unit)
  // 3. 支持响应中断 awaitUninterruptibly()

  // 示例：精确唤醒
  private final Lock lock = new ReentrantLock();
  private final Condition conditionA = lock.newCondition();
  private final Condition conditionB = lock.newCondition();

  // 可以单独唤醒等待 conditionA 的线程
  conditionA.signal();  // 只唤醒等待 conditionA 的线程

  // 而 notifyAll 会唤醒所有等待该锁的线程
  synchronized (lock) {
      lock.notifyAll();  // 无法区分是哪类线程
  }

  ┌─────────────────────────────────────────────────────────────┐
  │                        等待唤醒机制流程                         │

  线程 A (生产者)                        线程 B (消费者)
      │                                       │

      │  ┌─────┐                               │  ┌─────┐
      │  │等待区│                               │  │等待区│ (WAITING 状态)
      │  └─────┘                               │  └─────┘
      │                                       │
  线程 A (唤醒后) ← notifyAll() ←────────────┤

  常见面试问题

  // Q1: 为什么 wait/notify/notifyAll 定义在 Object 类中？
  // A: 因为这些方法需要操作对象的监视器锁，而 Java 中任何对象都可以作为锁
  //    如果定义在 Thread 类中，就只能用 Thread 对象作为锁，限制了灵活性

  // Q2: wait() 方法释放锁后，什么时候重新获取锁？
  // A: 被唤醒后，线程需要重新竞争获取锁，获取到锁后才能继续执行
  //    这就是为什么被唤醒后不一定立即执行，还要和其他线程竞争锁

  // Q3: notify() 和 notifyAll() 有什么区别？
  // A: notify() 随机唤醒一个等待线程，notifyAll() 唤醒所有等待线程
  //    通常建议使用 notifyAll()，因为 notify() 可能唤醒错误的线程导致信号丢失

  // Q4: 什么是虚假唤醒（Spurious Wakeup）？
  // A: 线程在没有被 notify 的情况下被唤醒，这是底层操作系统的特性
  //    解决方法：使用 while 循环重新检查条件

  // Q5: 如何避免死锁？
  // A: 1. 锁的获取顺序一致（所有线程按相同顺序获取多个锁）
  //    2. 设置超时（使用 tryLock(long timeout)）
  //    3. 减小锁的粒度（只锁必要的代码）
  //    4. 避免嵌套锁

  心得总结

  核心要点

  1. 集合选择：ArrayList 查找快，LinkedList 增删快，HashMap 无序，LinkedHashMap 有序
  2. 异常处理：try-catch-finally，throws 声明，throw 手动抛出
  3. IO 流：字节流可操作所有文件，字符流仅操作文本文件，记得关闭资源
  4. 多线程：synchronized 同步，Lock 手动锁，wait/notify 等待唤醒
  5. 网络编程：UDP 快但不可靠，TCP 慢但可靠

  常见坑点

  1. wait() 必须在同步代码块中用同一个锁对象调用
  2. 迭代器遍历不能使用集合的 remove 方法
  3. 字符串比较用 equals()，不用 ==
  4. equals() 和 hashCode() 必须一起重写
  5. finally 中不能有 return（会覆盖 try/catch 的返回值）
