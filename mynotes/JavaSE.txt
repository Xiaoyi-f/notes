  零、语法细节
  静态方法不能直接访问非静态字段，可以通过对象引用调用 
  {实例代码块，每次创建对象时候执行} static {静态代码块，类加载时执行一次}
  构造方法不能有返回值 void 
  支持方法重载
  super() 或者 this() 需要在构造方法的第一行 如果用了 super() 不能再用 this()
  静态方法中不能使用 this() 和 super() 
  finally {} 中 return 会覆盖 try/catch 中的 return 
  私有方法不能被继承 
  方法的重写规则 父类的方法不能比 子类 权限更低(例: public/protected -> public/protected Number -> Integer) 静态方法不能重写 
  接口可以作为类型 
  数组的 length 是 final 修饰的 数组长度是固定初始声明就要给有的
  内部类访问外部同名字段 -> Outer.this.x 
  访问内部类字段 -> this.x 
  访问外部类静态成员 -> Outer.x 
  方法中的内部类称为局部内部类 能够修改外部类的字段 不能修改方法中的局部变量(只读)  
  方法内部定义的局部类不能够有访问修饰符

  六、通配符

  1. 无界通配符 ?

  // ? 表示任意类型
  void printList(List<?> list) {
      for (Object e : list) {
          System.out.println(e);
      }
      // list.add("test");  // ❌ 不能添加元素（类型未知）
      // list.add(null);   // ✅ 只能添加 null

      Object o = list.get(0);  // ✅ 只能获取为 Object
  }

  // 使用场景：只读，不需要知道具体类型
  List<?> list = new ArrayList<String>();  // OK
  list = new ArrayList<Integer>();          // OK

  2. 上界通配符 ? extends T

  // ? extends Number：Number 或其子类
  void printNumbers(List<? extends Number> list) {
      // 只读（Producer）
      for (Number n : list) {
          System.out.println(n.doubleValue());
      }

      // ❌ 不能添加元素（可能是 List<Integer>，不能加 Double）
      // list.add(1);
      // list.add(1.5);
  }

  // 使用场景：读取数据（只读）
  List<? extends Number> list1 = new ArrayList<Integer>();
  List<? extends Number> list2 = new ArrayList<Double>();
  List<? extends Number> list3 = new ArrayList<Number>();

  // PECS 原则：Producer Extends（生产者用 extends）

  3. 下界通配符 ? super T

  // ? super Integer：Integer 或其父类
  void addIntegers(List<? super Integer> list) {
      // 只写（Consumer）
      list.add(1);      // ✅ Integer
      list.add(2.0);    // ✅ 自动装箱为 Integer

      // 读取只能到 Object
      // Integer i = list.get(0);  // ❌ 可能是 List<Number> 或
  List<Object>
      Object o = list.get(0);     // ✅
  }

  // 使用场景：写入数据（只写）
  List<? super Integer> list1 = new ArrayList<Integer>();
  List<? super Integer> list2 = new ArrayList<Number>();
  List<? super Integer> list3 = new ArrayList<Object>();

  // PECS 原则：Consumer Super（消费者用 super）

  4. PECS 原则总结

  // PECS: Producer Extends, Consumer Super

  // Producer - 生产者，从集合取数据
  public static double sum(List<? extends Number> list) {
      double total = 0;
      for (Number n : list) {  // 取数据
          total += n.doubleValue();
      }
      return total;
  }

  // Consumer - 消费者，向集合存数据
  public static void addAll(List<? super Integer> list, int...
  values) {
      for (int v : values) {
          list.add(v);  // 存数据
      }
  }

  擦除规则

  ┌─────────────────────────────────┬──────────────────────┐
  │            泛型声明             │     擦除后的类型     │
  ├─────────────────────────────────┼──────────────────────┤

  擦除示例

  // 原代码
  public class Box<T> {
      private T value;

      public void set(T value) {
          this.value = value;
      }

      public T get() {
          return value;
      }
  }

  // 擦除后（编译器生成）

      }
  }

  擦除的影响

  // 1. 不能创建泛型数组
  // List<String>[] arr = new List<String>[10];  // ❌ 编译错误
  List<?>[] arr = new List<?>[10];  // ✅

  强制转换，不安全

  // 2. 不能实例化类型参数

  十二、常见面试题

  Q1: 泛型的作用？
  - 类型安全：编译期检查，避免 ClassCastException
  - 代码复用：同一套逻辑支持多种类型
  - 消除强转：代码更简洁

  Q2: 什么是类型擦除？
  - Java 泛型是编译时特性，编译后擦除为原始类型
  - 无边界擦除到 Object，有边界擦除到边界类型
  - 运行时无法获取泛型类型信息

  Q3: List<?>、List<? extends T>、List<? super T> 的区别？
  - List<?>：任意类型，只能读取为 Object，不能添加
  - List<? extends T>：T 或子类，只读（Producer）
  - List<? super T>：T 或父类，只写（Consumer）

  Q4: 为什么不能用基本类型作为泛型参数？
  - 泛型擦除后变为 Object，基本类型不是 Object 的子类
  - 使用包装类代替（int → Integer）

  Q5: 什么是 PECS 原则？
  - Producer Extends：生产者用 ? extends T（读取）
  - Consumer Super：消费者用 ? super T（写入）

  十三、注意事项

  1. 不能用基本类型 - List<int> ❌，用 List<Integer> ✅
  2. 不能创建泛型数组 - new List<String>[10] ❌
  3. 不能实例化类型参数 - new T() ❌
  4. 静态成员不能使用类型参数 - private static T value ❌
  5. 泛型方法不使用类类型参数 - 方法上的 <T> 独立定义
  6. 通配符不能用于泛型类定义 - class Box<?> ❌
  7. equals 和 hashCode 谨慎使用泛型 - 可能哈希冲突

  等待唤醒机制（详解）

  核心概念

  等待唤醒机制是多线程间通信的一种方式，让线程可以：
  - 在某个条件不满足时等待（释放锁，进入等待状态）
  - 在条件满足后被其他线程唤醒（重新获取锁，继续执行）

  基本方法（Object 类）

  import java.lang.*;

  // 这些方法必须在同步代码块或同步方法中使用，且必须用同一个锁对象调用
  obj.wait();          // 当前线程等待，释放锁对象
  obj.wait(long timeout);  // 等待指定毫秒数，超时自动唤醒
  obj.notify();        // 随机唤醒一个等待该锁对象的线程
  obj.notifyAll();     // 唤醒所有等待该锁对象的线程

  为什么必须在同步中使用？

  // 错误示例 - 会抛出 IllegalMonitorStateException
  Object lock = new Object();
  lock.wait();  // ❌ 没有获取锁就调用 wait()

  // 正确示例
  synchronized (lock) {
      lock.wait();  // ✅ 已获取锁，可以调用
  }

  原因：wait() 需要释放当前线程持有的锁，如果没有持有锁就无法释放，所以 Java 强制要求必须在同步代码中使用。

  生产者消费者模式（经典案例）

  import java.util.LinkedList;
  import java.util.Queue;

  public class ProducerConsumer {
      // 共享数据容器
      private static final Queue<String> queue = new LinkedList<>();
      private static final int MAX_SIZE = 5;
      private static final Object LOCK = new Object(); // 必须是同一个锁对象

      public static void main(String[] args) {
          // 生产者线程
          Thread producer = new Thread(() -> {
              for (int i = 1; i <= 20; i++) {
                  synchronized (LOCK) {
                      // 如果队列满了，生产者等待
                      while (queue.size() >= MAX_SIZE) {
                          try {
                              System.out.println("队列已满，生产者等待...");
                              LOCK.wait();  // 释放锁，进入等待状态
                          } catch (InterruptedException e) {
                              e.printStackTrace();
                          }
                      }

                      // 生产产品
                      String product = "产品" + i;
                      queue.offer(product);
                      System.out.println("生产: " + product + "，当前数量: " + queue.size());

                      // 唤醒消费者
                      LOCK.notifyAll();  // 唤醒所有等待该锁的线程
                  }

                  try {
                      Thread.sleep(100);  // 模拟生产耗时
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
              }
          }, "生产者");

          // 消费者线程
          Thread consumer = new Thread(() -> {
              while (true) {
                  synchronized (LOCK) {
                      // 如果队列空了，消费者等待
                      while (queue.isEmpty()) {
                          try {
                              System.out.println("队列为空，消费者等待...");
                              LOCK.wait();  // 释放锁，进入等待状态
                          } catch (InterruptedException e) {
                              e.printStackTrace();
                          }
                      }

                      // 消费产品
                      String product = queue.poll();
                      System.out.println("消费: " + product + "，当前数量: " + queue.size());

                      // 唤醒生产者
                      LOCK.notifyAll();  // 唤醒所有等待该锁的线程
                  }

                  try {
                      Thread.sleep(200);  // 模拟消费耗时
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
              }
          }, "消费者");

          producer.start();
          consumer.start();
      }
  }

  为什么用 while 而不是 if？

  // ❌ 错误写法 - 使用 if
  synchronized (LOCK) {
      if (queue.isEmpty()) {
          LOCK.wait();  // 被唤醒后不会重新检查条件
      }
      // 如果被虚假唤醒（spurious wakeup），可能执行到此处时队列仍是空的
      String product = queue.poll();  // 可能返回 null！
  }

  // ✅ 正确写法 - 使用 while
  synchronized (LOCK) {
      while (queue.isEmpty()) {  // 被唤醒后会重新检查条件
          LOCK.wait();
      }
      // 保证队列一定有元素
      String product = queue.poll();
  }

  原因：wait() 可能被虚假唤醒（spurious wakeup），操作系统可能会在没有 notify 的情况下唤醒线程。使用 while 循环可以确保被唤醒后重新检查条件是否满足。

  wait() 与 sleep() 的区别

  // sleep() - Thread 类的静态方法
  Thread.sleep(1000);
  // 1. 不释放锁（如果在同步代码块中）
  // 2. 必须传入时间，不能被 notify 唤醒
  // 3. 时间到自动唤醒

  // wait() - Object 类的实例方法
  synchronized (obj) {
      obj.wait();           // 等待直到被 notify
      obj.wait(1000);       // 等待最多 1000 毫秒
  }
  // 1. 会释放锁
  // 2. 必须在同步代码中用同一个锁对象调用
  // 3. 可以被 notify / notifyAll 唤醒，也可以超时自动唤醒

  // 演示区别
  public class WaitSleepDemo {
      private static final Object LOCK = new Object();

      public static void main(String[] args) {
          // sleep 不释放锁
          Thread t1 = new Thread(() -> {
              synchronized (LOCK) {
                  System.out.println("Thread1 获取锁，开始 sleep");
                  try {
                      Thread.sleep(2000);  // sleep 期间持有锁
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
                  System.out.println("Thread1 sleep 结束，释放锁");
              }
          });

          // wait 释放锁
          Thread t2 = new Thread(() -> {
              try {
                  Thread.sleep(100);  // 让 t1 先执行
              } catch (InterruptedException e) {
                  e.printStackTrace();
              }
              synchronized (LOCK) {
                  System.out.println("Thread2 获取锁，开始 wait");
                  try {
                      LOCK.wait();  // wait 期间释放锁
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
                  System.out.println("Thread2 被唤醒");
              }
          });

          Thread t3 = new Thread(() -> {
              try {
                  Thread.sleep(1500);  // 等待合适时机
              } catch (InterruptedException e) {
                  e.printStackTrace();
              }
              synchronized (LOCK) {
                  System.out.println("Thread3 获取锁，唤醒 t2");
                  LOCK.notifyAll();
              }
          });

          t1.start();
          t2.start();
          t3.start();
      }
  }

  Condition 接口（Lock 的等待唤醒机制）

  import java.util.concurrent.locks.*;

  public class ConditionDemo {
      private static final Lock lock = new ReentrantLock();
      private static final Condition notFull = lock.newCondition();  // 生产者等待条件
      private static final Condition notEmpty = lock.newCondition(); // 消费者等待条件

      private static final Queue<String> queue = new LinkedList<>();
      private static final int MAX_SIZE = 5;

      public static void main(String[] args) {
          Thread producer = new Thread(() -> {
              for (int i = 1; i <= 20; i++) {
                  lock.lock();
                  try {
                      while (queue.size() >= MAX_SIZE) {
                          System.out.println("队列已满，生产者等待...");
                          notFull.await();  // 类似 wait()，但会释放 lock
                      }

                      String product = "产品" + i;
                      queue.offer(product);
                      System.out.println("生产: " + product + "，当前数量: " + queue.size());

                      notEmpty.signal();  // 唤醒消费者（类似 notify）
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  } finally {
                      lock.unlock();
                  }

                  try {
                      Thread.sleep(100);
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
              }
          }, "生产者");

          Thread consumer = new Thread(() -> {
              while (true) {
                  lock.lock();
                  try {
                      while (queue.isEmpty()) {
                          System.out.println("队列为空，消费者等待...");
                          notEmpty.await();
                      }

                      String product = queue.poll();
                      System.out.println("消费: " + product + "，当前数量: " + queue.size());

                      notFull.signal();  // 唤醒生产者
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  } finally {
                      lock.unlock();
                  }

                  try {
                      Thread.sleep(200);
                  } catch (InterruptedException e) {
                      e.printStackTrace();
                  }
              }
          }, "消费者");

          producer.start();
          consumer.start();
      }
  }

  Condition 与 Object wait/notify 的优势

  // Object wait/notify 的限制
  // 1. 只能有一个等待队列（所有等待同一锁的线程都在一个队列）
  // 2. notify() 随机唤醒一个，不能精确唤醒特定类型的线程
  // 3. 不支持超时等待（需要用 wait(long timeout)）

  // Condition 的优势
  // 1. 可以创建多个 Condition，实现精确唤醒
  // 2. 支持超时等待 await(long time, TimeUnit unit)
  // 3. 支持响应中断 awaitUninterruptibly()

  // 示例：精确唤醒
  private final Lock lock = new ReentrantLock();
  private final Condition conditionA = lock.newCondition();
  private final Condition conditionB = lock.newCondition();

  // 可以单独唤醒等待 conditionA 的线程
  conditionA.signal();  // 只唤醒等待 conditionA 的线程

  // 而 notifyAll 会唤醒所有等待该锁的线程
  synchronized (lock) {
      lock.notifyAll();  // 无法区分是哪类线程
  }

  常见面试问题

  // Q1: 为什么 wait/notify/notifyAll 定义在 Object 类中？
  // A: 因为这些方法需要操作对象的监视器锁，而 Java 中任何对象都可以作为锁
  //    如果定义在 Thread 类中，就只能用 Thread 对象作为锁，限制了灵活性

  // Q2: wait() 方法释放锁后，什么时候重新获取锁？
  // A: 被唤醒后，线程需要重新竞争获取锁，获取到锁后才能继续执行
  //    这就是为什么被唤醒后不一定立即执行，还要和其他线程竞争锁

  // Q3: notify() 和 notifyAll() 有什么区别？
  // A: notify() 随机唤醒一个等待线程，notifyAll() 唤醒所有等待线程
  //    通常建议使用 notifyAll()，因为 notify() 可能唤醒错误的线程导致信号丢失

  // Q4: 什么是虚假唤醒（Spurious Wakeup）？
  // A: 线程在没有被 notify 的情况下被唤醒，这是底层操作系统的特性
  //    解决方法：使用 while 循环重新检查条件

  // Q5: 如何避免死锁？
  // A: 1. 锁的获取顺序一致（所有线程按相同顺序获取多个锁）
  //    2. 设置超时（使用 tryLock(long timeout)）
  //    3. 减小锁的粒度（只锁必要的代码）
  //    4. 避免嵌套锁

  心得总结

  核心要点

  1. 集合选择：ArrayList 查找快，LinkedList 增删快，HashMap 无序，LinkedHashMap 有序
  2. 异常处理：try-catch-finally，throws 声明，throw 手动抛出
  3. IO 流：字节流可操作所有文件，字符流仅操作文本文件，记得关闭资源
  4. 多线程：synchronized 同步，Lock 手动锁，wait/notify 等待唤醒
  5. 网络编程：UDP 快但不可靠，TCP 慢但可靠

  常见坑点

  1. wait() 必须在同步代码块中用同一个锁对象调用
  2. 迭代器遍历不能使用集合的 remove 方法
  3. 字符串比较用 equals()，不用 ==
  4. equals() 和 hashCode() 必须一起重写
  5. finally 中不能有 return（会覆盖 try/catch 的返回值）
