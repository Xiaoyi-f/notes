SQL语句一般返回原始的、无格式的数据，不同的DBMS和客户端显示数据的方式略有不同（如对齐格式不同、小数位数不同）
一般而言，除非你确实需要表中的每一列，否则最好别使用＊通配符。虽然使用通配符能让你自己省事，不用明确列出所需列，
但检索不需要的列通常会降低检索速度和应用程序的性能

操作符 作用 是否去重
UNION 合并两个结果集 ✅ 去重
UNION ALL 合并两个结果集 ❌ 不去重
INTERSECT 返回两个结果集的交集 ✅ 去重
EXCEPT / MINUS 返回第一个结果集有、第二个没有的行 ✅ 去重

注意：MySQL 不支持 INTERSECT 和 EXCEPT（可用其他写法替代），但 PostgreSQL、SQL Server、Oracle 都支持

硬性要求：
1. 列数相同
2. 对应列的数据类型兼容（能隐式转换）
3. 最终结果的列名以第一个 SELECT 的列名为准
4. 允许各自有 WHERE、GROUP BY，但不能在整个组合查询后统一用 ORDER BY（只能在最后对整个结果排序，且必须跟在最后一个 SELECT 后面）

SELECT 列1, 列2 FROM 表A
UNION [ALL | INTERSECT | EXCEPT]
SELECT 列1, 列2 FROM 表B;

-- 组合查询：把今年和去年的销售记录上下拼在一起
SELECT 产品, 金额, 2023 AS 年份 FROM 销售额2023
UNION ALL
SELECT 产品, 金额, 2024 FROM 销售额2024;

-- 联结：把产品表和订单表左右拼在一起查产品详情
SELECT * FROM 订单 LEFT JOIN 产品 ON 订单.产品ID = 产品.ID;

1. UNION 自动去重会排序，大数据量时慢；明确不需要去重用 UNION ALL
2. ORDER BY 只能出现在最后，且必须使用第一个 SELECT 中的列名或别名
   (SELECT 产品, 金额 FROM 2023) UNION (SELECT 产品, 金额 FROM 2024) ORDER BY 金额 DESC;

3. 括号的作用：默认从左到右执行，但可以用括号改变顺序（尤其在混合 UNION 和 INTERSECT 时，推荐加括号明确优先级）
4. MySQL 替代方案：
   · INTERSECT → INNER JOIN 或 EXISTS
   · EXCEPT → NOT EXISTS 或 LEFT JOIN ... WHERE B.ID IS NULL
