# SQL 学习笔记 - 面试高频考点汇总

## 一、SQL 基础

### 1.1 SQL 语句执行顺序

**Q: SQL 语句的执行顺序是什么？**

**A:** 书写顺序 vs 执行顺序：

```sql
-- 书写顺序
SELECT 
FROM
WHERE
GROUP BY
HAVING
ORDER BY
LIMIT

-- 实际执行顺序
FROM       -- 确定数据源
WHERE      -- 过滤数据
GROUP BY   -- 分组
HAVING     -- 过滤分组
SELECT     -- 选择列
ORDER BY   -- 排序
LIMIT      -- 限制结果数
```

---

### 1.2 WHERE vs HAVING

**Q: WHERE 和 HAVING 的区别？**

**A:**

| 特性 | WHERE | HAVING |
|------|-------|--------|
| **执行时机** | 分组前过滤 | 分组后过滤 |
| **过滤对象** | 原始行 | 分组结果 |
| **聚合函数** | 不能使用 | 可以使用 |
| **执行顺序** | 最先执行 | GROUP BY 之后 |

```sql
-- ✅ 正确
SELECT department, COUNT(*) 
FROM employees 
WHERE status = 'active'       -- WHERE：分组前过滤
GROUP BY department
HAVING COUNT(*) > 5;          -- HAVING：分组后过滤

-- ❌ 错误：WHERE 不能使用聚合函数
SELECT department, COUNT(*) 
FROM employees 
WHERE COUNT(*) > 5             -- 错误
GROUP BY department;
```

---

### 1.3 DISTINCT 注意事项

**Q: DISTINCT 有哪些注意事项？**

**A:**

1. **作用于所有列**：DISTINCT 作用于所有列，不仅仅是后一列
2. **不能用于 COUNT(*)**
3. **数据量大会影响性能**

```sql
-- ✅ 正确
SELECT COUNT(DISTINCT department) FROM employees;
SELECT COUNT(DISTINCT name) FROM employees;

-- ❌ 错误
SELECT COUNT(DISTINCT *) FROM employees;

-- ⚠️ 注意：这里是对整个组合去重
SELECT DISTINCT department, name FROM employees;
```

---

### 1.4 LIMIT 分页

**Q: 不同数据库的分页语法？**

**A:**

| 数据库 | 语法 |
|--------|------|
| **MySQL** | `LIMIT n OFFSET m` 或 `LIMIT m, n` |
| **PostgreSQL** | `LIMIT n OFFSET m` |
| **Oracle** | `OFFSET m ROWS FETCH NEXT n ROWS ONLY` |
| **SQL Server** | `OFFSET m ROWS FETCH NEXT n ROWS ONLY` |

```sql
-- MySQL/PostgreSQL
SELECT * FROM users LIMIT 10 OFFSET 5;
SELECT * FROM users LIMIT 5, 10;  -- MySQL 简写

-- 分页公式
SELECT * FROM users LIMIT pageSize OFFSET (page - 1) * pageSize;
```

## 二、JOIN 连接

### 2.1 连接类型对比

**Q: 有哪些连接类型？**

**A:**

| 连接类型 | 说明 | 使用场景 |
|----------|------|----------|
| **INNER JOIN** | 内连接，只匹配两边都存在的记录 | 查询有订单的用户 |
| **LEFT JOIN** | 左连接，保留左表所有记录 | 查询所有用户及其订单 |
| **RIGHT JOIN** | 右连接，保留右表所有记录 | 查询所有订单及其用户 |
| **FULL OUTER JOIN** | 全连接，保留两边所有记录 | 查询所有用户和订单 |
| **CROSS JOIN** | 交叉连接，笛卡尔积 | 生成所有可能组合 |

---

### 2.2 LEFT JOIN vs RIGHT JOIN

**Q: LEFT JOIN 和 RIGHT JOIN 的区别？**

**A:** LEFT JOIN 保留左表所有记录，RIGHT JOIN 保留右表所有记录。

**实际应用：RIGHT JOIN 很少使用，通常用 LEFT JOIN 替代**

```sql
-- RIGHT JOIN
SELECT * FROM users RIGHT JOIN orders ON users.id = orders.user_id;

-- 等价写法（推荐）
SELECT * FROM orders LEFT JOIN users ON users.id = orders.user_id;
```

---

### 2.3 自连接

**Q: 什么是自连接？有哪些使用场景？**

**A:** 自连接是将一个表当作两个表来用。

**使用场景：**
1. 查询员工的上级信息
2. 查询同部门员工
3. 查询商品关联商品

```sql
-- 查询员工及其上级
SELECT 
    e.name AS employee,
    m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;

-- 查询同部门员工
SELECT 
    e1.name AS employee1,
    e2.name AS employee2
FROM employees e1
JOIN employees e2 ON e1.department_id = e2.department_id
WHERE e1.id < e2.id;  -- 避免重复配对
```

---

### 2.4 JOIN vs 子查询

**Q: JOIN 和子查询哪个效率更高？**

**A:** 通常 JOIN 效率更高，但具体取决于场景和数据库优化器。

| 特性 | JOIN | 子查询 |
|------|------|--------|
| **可读性** | 需要理解连接 | 直观 |
| **性能** | 通常较快 | 可能较慢 |
| **MySQL优化** | 好 | 有限 |

```sql
-- 子查询方式
SELECT * FROM users
WHERE id IN (SELECT user_id FROM orders WHERE amount > 1000);

-- JOIN 方式（推荐）
SELECT DISTINCT u.* FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.amount > 1000;

-- EXISTS 方式（有时比 JOIN 快）
SELECT u.* FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id AND o.amount > 1000);
```

## 三、聚合与分组

### 3.1 聚合函数

**Q: 常用聚合函数有哪些？**

**A:** COUNT、SUM、AVG、MAX、MIN

```sql
SELECT 
    COUNT(*) AS total,                    -- 总行数
    COUNT(department) AS departments,    -- 非NULL值数量
    SUM(salary) AS total_salary,         -- 总和
    AVG(salary) AS avg_salary,           -- 平均值
    MAX(salary) AS max_salary,           -- 最大值
    MIN(salary) AS min_salary            -- 最小值
FROM employees;
```

---

### 3.2 GROUP BY 规则

**Q: GROUP BY 的规则是什么？**

**A:** SELECT 中的非聚合列必须在 GROUP BY 中。

```sql
-- ❌ 错误：name 不在 GROUP BY 中
SELECT department, name, COUNT(*) FROM employees GROUP BY department;

-- ✅ 正确
SELECT department, COUNT(*) FROM employees GROUP BY department;

-- 或使用 ANY_VALUE()（MySQL）
SELECT department, ANY_VALUE(name), COUNT(*) FROM employees GROUP BY department;
```

---

### 3.3 GROUP BY 优化

**Q: 如何优化 GROUP BY 查询？**

**A:**

1. **添加索引**：为 GROUP BY 的列添加索引
2. **避免 SELECT ***
3. **使用覆盖索引**
4. **优化 WHERE 条件**

```sql
-- ✅ 优化：添加索引
CREATE INDEX idx_department_salary ON employees(department, salary);

-- ✅ 优化：只选择需要的列
SELECT department, COUNT(*) FROM employees GROUP BY department;
```

## 四、窗口函数

### 4.1 窗口函数基础

**Q: 窗口函数的语法是什么？**

**A:**

```sql
function_name() OVER (
    PARTITION BY column1, column2  -- 分组
    ORDER BY column3                -- 排序
    frame_clause                    -- 窗口范围
)
```

---

### 4.2 排名函数

**Q: RANK、DENSE_RANK、ROW_NUMBER 的区别？**

**A:**

| 函数 | 说明 | 示例 |
|------|------|------|
| **ROW_NUMBER()** | 顺序排名 | 1,2,3,4 |
| **RANK()** | 跳跃排名 | 1,2,2,4 |
| **DENSE_RANK()** | 密集排名 | 1,2,2,3 |

```sql
SELECT 
    name,
    salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num,
    RANK() OVER (ORDER BY salary DESC) AS rank,
    DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rank
FROM employees;

-- 结果示例：
-- name  | salary | row_num | rank | dense_rank
-- ----- | ------ | ------- | ----- | ----------
-- 张三  | 10000  | 1       | 1     | 1
-- 李四  | 9000   | 2       | 2     | 2
-- 王五  | 9000   | 3       | 2     | 2
-- 赵六  | 8000   | 4       | 4     | 3
```

---

### 4.3 LAG 和 LEAD

**Q: LAG 和 LEAD 的作用？**

**A:** LAG 获取前一行，LEAD 获取后一行。

```sql
SELECT 
    order_date,
    amount,
    LAG(amount) OVER (ORDER BY order_date) AS prev_amount,
    LEAD(amount) OVER (ORDER BY order_date) AS next_amount,
    amount - LAG(amount) OVER (ORDER BY order_date) AS diff
FROM orders;
```

## 五、子查询

### 5.1 子查询类型

**Q: 有哪些子查询类型？**

**A:**

| 类型 | 说明 | 位置 |
|------|------|------|
| **标量子查询** | 返回单行单列 | WHERE、SELECT |
| **列子查询** | 返回单列多行 | WHERE、HAVING |
| **行子查询** | 返回单行多列 | WHERE |
| **表子查询** | 返回多行多列 | FROM |

---

### 5.2 EXISTS vs IN

**Q: EXISTS 和 IN 的区别？哪个更高效？**

**A:**

| 特性 | IN | EXISTS |
|------|----|--------|
| **语法** | `WHERE id IN (...)` | `WHERE EXISTS (...)` |
| **处理** | 先执行子查询 | 逐行检查 |
| **效率** | 结果少时快 | 结果多时快 |

**通常 EXISTS 更高效**

```sql
-- IN 方式
SELECT * FROM users u
WHERE u.id IN (SELECT user_id FROM orders o WHERE o.amount > 1000);

-- EXISTS 方式（推荐）
SELECT * FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o 
    WHERE o.user_id = u.id AND o.amount > 1000
);
```

## 六、事务

### 6.1 ACID 特性

**Q: 事务的 ACID 特性是什么？**

**A:**

| 特性 | 说明 |
|------|------|
| **原子性**（Atomicity） | 事务中的操作要么全部成功，要么全部失败 |
| **一致性**（Consistency） | 事务执行前后，数据库状态保持一致 |
| **隔离性**（Isolation） | 多个事务并发执行时，互不干扰 |
| **持久性**（Durability） | 事务提交后，结果永久保存 |

---

### 6.2 隔离级别

**Q: 事务的隔离级别有哪些？**

**A:**

| 隔离级别 | MySQL 默认 | 脏读 | 不可重复读 | 幻读 |
|----------|------------|------|------------|------|
| **READ UNCOMMITTED** | | ✅ | ✅ | ✅ |
| **READ COMMITTED** | | ❌ | ✅ | ✅ |
| **REPEATABLE READ** | ✅ | ❌ | ❌ | ✅ |
| **SERIALIZABLE** | | ❌ | ❌ | ❌ |

**并发问题：**
- **脏读**：读取了未提交的数据
- **不可重复读**：同一事务中，两次读取同一数据结果不同
- **幻读**：同一事务中，两次查询结果集不同

---

### 6.3 事务失效场景

**Q: 哪些情况下事务会失效？**

**A:**

1. **MyISAM 引擎不支持事务**（必须用 InnoDB）
2. **DDL 语句不能回退**（CREATE、DROP、ALTER）
3. **TRUNCATE 无法回退**（MySQL）
4. **未正确开启事务**（自动提交）
5. **错误被捕获但未回滚**

## 七、索引

### 7.1 索引类型

**Q: 常见的索引类型有哪些？**

**A:** 普通、唯一、复合、全文、空间

---

### 7.2 复合索引

**Q: 复合索引的最左前缀原则是什么？**

**A:** 复合索引按从左到右的顺序匹配。

```sql
-- 创建复合索引
CREATE INDEX idx_name_age ON users(name, age);

-- ✅ 可以使用索引
SELECT * FROM users WHERE name = '张三';
SELECT * FROM users WHERE name = '张三' AND age = 25;
SELECT * FROM users WHERE name = '张三' AND age > 20;

-- ❌ 无法使用索引
SELECT * FROM users WHERE age = 25;  -- 跳过最左列
SELECT * FROM users WHERE age = 25 AND name = '张三';  -- 顺序不对
```

---

### 7.3 索引失效场景

**Q: 哪些情况下索引会失效？**

**A:**

1. **对列使用函数**
2. **隐式类型转换**
3. **使用 OR**（部分情况）
4. **LIKE 以通配符开头**
5. **NOT IN、!=、<>**
6. **WHERE 和 ORDER BY 使用不同索引**

```sql
-- ❌ 索引失效
SELECT * FROM users WHERE YEAR(created_at) = 2024;
SELECT * FROM users WHERE phone = 13800138000;  -- phone 是 VARCHAR
SELECT * FROM users WHERE name LIKE '%张%';

-- ✅ 优化
SELECT * FROM users WHERE created_at >= '2024-01-01' AND created_at < '2025-01-01';
SELECT * FROM users WHERE phone = '13800138000';
SELECT * FROM users WHERE name LIKE '张%';
```

---

### 7.4 适合建索引的列

**Q: 哪些列适合创建索引？**

**A:**

| 适合建索引 | 不适合建索引 |
|-----------|-------------|
| 主键 | 低基数列（性别、状态） |
| 外键 | 频繁更新的列 |
| WHERE 条件常用列 | 大文本列 |
| ORDER BY 列 | 很少查询的列 |
| JOIN 条件列 | 表数据量很小 |

### 8.2 聚簇索引

**Q: 什么是聚簇索引？一张表可以有几个聚簇索引？**

**A:** 聚簇索引是索引和数据存储在一起，按主键顺序存储。

**一张表只能有一个聚簇索引**（通常是主键）

### 8.3 JSON 类型

**Q: MySQL 的 JSON 类型支持哪些操作？**

**A:**

```sql
-- 创建 JSON 列
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    attributes JSON
);

-- 查询 JSON
SELECT attributes->>'$.brand' FROM products;

-- 修改 JSON
UPDATE products SET attributes = JSON_SET(attributes, '$.price', 100);

-- JSON 索引（虚拟列）
ALTER TABLE products 
ADD COLUMN brand VARCHAR(50) GENERATED ALWAYS AS (attributes->>'$.brand') STORED,
ADD INDEX idx_brand (brand);
```

### 9.2 UPSERT

**Q: PostgreSQL 如何实现 UPSERT？**

**A:** 使用 `INSERT ... ON CONFLICT`

```sql
INSERT INTO users (id, name, email)
VALUES (1, '张三', 'zhangsan@example.com')
ON CONFLICT (id) 
DO UPDATE SET 
    name = EXCLUDED.name,
    email = EXCLUDED.email,
    updated_at = NOW()
WHERE users.id = EXCLUDED.id;
```

---

### 9.3 数组类型

**Q: PostgreSQL 的数组类型如何使用？**

**A:**

```sql
-- 创建数组列
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    tags INT[],
    emails VARCHAR(100)[]
);

-- 插入数组
INSERT INTO users (tags) VALUES (ARRAY[1,2,3]);

-- 查询数组
SELECT tags[1] FROM users;  -- 索引从1开始
SELECT * FROM users WHERE 2 = ANY(tags);  -- 包含2
```

### 10.2 CRUD 操作

**Q: MongoDB 的 CRUD 操作？**

**A:**

```javascript
// 插入
db.users.insertOne({ name: "张三", age: 25 });

// 查询
db.users.find({ age: { $gte: 25 } });

// 更新
db.users.updateOne(
    { name: "张三" },
    { $set: { age: 26 } }
);

// 删除
db.users.deleteOne({ name: "张三" });
```

---

### 10.3 聚合管道

**Q: MongoDB 的聚合管道有哪些常用操作？**

**A:** $match、$group、$project、$sort、$limit、$skip、$lookup

```javascript
db.orders.aggregate([
    { $match: { amount: { $gte: 100 } } },
    {
        $group: {
            _id: "$userId",
            totalAmount: { $sum: "$amount" },
            avgAmount: { $avg: "$amount" }
        }
    },
    { $sort: { totalAmount: -1 } }
]);
```
