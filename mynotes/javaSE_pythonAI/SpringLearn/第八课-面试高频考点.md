## 一、Spring 核心基础

### 1. IoC 和 DI ⭐⭐⭐

**Q: 什么是 IoC？**

IoC（Inversion of Control，控制反转）是一种设计思想，将对象的创建和管理权交给容器，而不是自己创建。

**Q: 什么是 DI？**

DI（Dependency Injection，依赖注入）是 IoC 的实现方式，容器主动将依赖对象注入到目标对象中。

**Q: IoC 和 DI 的关系？**

IoC 是思想，DI 是实现。

**Q: DI 的三种注入方式？**

1. 字段注入：`@Autowired` 修饰字段
2. 构造器注入：通过构造器注入（推荐）
3. Setter 注入：通过 Setter 方法注入

---

### 2. Bean 的生命周期 ⭐⭐⭐

**Q: Bean 的生命周期？**

```
实例化 → 属性赋值 → 初始化 → 使用 → 销毁
   ↓           ↓         ↓       ↓      ↓
构造器    @Autowired  @PostConstruct  @PreDestroy
```

**Q: Bean 的作用域？**

| 作用域 | 说明 |
|--------|------|
| `singleton` | 容器中只有一个实例（默认） |
| `prototype` | 每次获取都创建新实例 |
| `request` | 每个 HTTP 请求一个实例 |
| `session` | 每个 HTTP Session 一个实例 |

**Q: @PostConstruct 和 @PreDestroy 的执行时机？**

- `@PostConstruct`：初始化后执行
- `@PreDestroy`：销毁前执行

### 3. AOP ⭐⭐⭐

**Q: 什么是 AOP？**

AOP（Aspect Oriented Programming，面向切面编程）通过预编译和运行期动态代理实现程序功能的统一维护，解决横切关注点问题。

**Q: AOP 的核心概念？**

| 概念 | 说明 |
|------|------|
| 切面（Aspect） | 横切关注点的模块化 |
| 连接点（JoinPoint） | 程序执行的特定位置 |
| 切入点（Pointcut） | 匹配连接点的表达式 |
| 通知（Advice） | 在切入点执行的操作 |
| 目标对象（Target） | 被代理的对象 |
| 代理（Proxy） | AOP 框架创建的对象 |
| 织入（Weaving） | 将切面应用到目标对象 |

**Q: AOP 的通知类型？**

| 类型 | 注解 | 执行时机 |
|------|------|----------|
| 前置通知 | `@Before` | 目标方法执行前 |
| 后置通知 | `@After` | 目标方法执行后 |
| 返回通知 | `@AfterReturning` | 目标方法成功返回后 |
| 异常通知 | `@AfterThrowing` | 目标方法抛出异常后 |
| 环绕通知 | `@Around` | 目标方法执行前后 |

**Q: AOP 实现原理？**

- **JDK 动态代理**：目标类实现了接口
- **CGLIB 代理**：目标类未实现接口

**Q: Spring AOP 和 AspectJ 的区别？**

| 特性 | Spring AOP | AspectJ |
|------|------------|---------|
| 实现方式 | 运行期动态代理 | 编译期织入 |
| 性能 | 较低 | 较高 |
| 功能 | 仅支持方法级别 | 支持字段、构造器等 |

### 4. 事务管理 ⭐⭐⭐

**Q: @Transactional 的属性？**

| 属性 | 说明 |
|------|------|
| `propagation` | 传播行为 |
| `isolation` | 隔离级别 |
| `rollbackFor` | 回滚异常 |
| `noRollbackFor` | 不回滚异常 |
| `timeout` | 超时时间 |
| `readOnly` | 只读事务 |

**Q: 事务传播行为？**

| 类型 | 说明 |
|------|------|
| `REQUIRED`（默认） | 有事务则加入，无则创建 |
| `REQUIRES_NEW` | 创建新事务，挂起当前事务 |
| `SUPPORTS` | 有事务则加入，无则非事务执行 |
| `NOT_SUPPORTED` | 以非事务方式执行 |
| `MANDATORY` | 必须在事务中执行 |
| `NEVER` | 以非事务方式执行，有事务则抛异常 |
| `NESTED` | 嵌套事务 |

**Q: 事务隔离级别？**

| 级别 | 说明 | 问题 |
|------|------|------|
| `READ_UNCOMMITTED` | 读未提交 | 脏读、不可重复读、幻读 |
| `READ_COMMITTED` | 读已提交 | 不可重复读、幻读 |
| `REPEATABLE_READ` | 可重复读 | 幻读 |
| `SERIALIZABLE` | 串行化 | 无问题，性能差 |

**Q: 事务失效的场景？**

1. 方法不是 public
2. 方法内部调用
3. 异常被捕获未抛出
4. 没有在 @Transactional 方法中
5. 类没有被 Spring 管理

## 二、Spring Boot

### 5. 自动配置原理 ⭐⭐⭐

**Q: Spring Boot 自动配置原理？**

1. `@EnableAutoConfiguration` 导入 `AutoConfigurationImportSelector`
2. 读取 `spring.factories` 文件获取所有自动配置类
3. 通过 `@Conditional` 系列注解按需加载
4. 满足条件的自动配置类创建 Bean

**Q: @Conditional 系列注解？**

| 注解 | 条件 |
|------|------|
| `@ConditionalOnClass` | 类路径下存在指定类 |
| `@ConditionalOnMissingClass` | 类路径下不存在指定类 |
| `@ConditionalOnBean` | 容器中存在指定 Bean |
| `@ConditionalOnMissingBean` | 容器中不存在指定 Bean |
| `@ConditionalOnProperty` | 配置文件中指定属性匹配 |
| `@ConditionalOnWebApplication` | 是 Web 应用 |

**Q: 如何禁用自动配置？**

```java
@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)
```

或配置文件：

```yaml
spring:
  autoconfigure:
    exclude:
      - org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration
```

---

### 6. 启动流程 ⭐⭐

**Q: Spring Boot 启动流程？**

1. 创建 `SpringApplication` 对象
2. 执行 `run()` 方法
3. 准备 `Environment`
4. 创建 `ApplicationContext`
5. 刷新容器
6. 调用 `CommandLineRunner` 和 `ApplicationRunner`

**Q: @SpringBootApplication 包含哪些注解？**

```java
@SpringBootConfiguration  // 标识为配置类
@EnableAutoConfiguration  // 启用自动配置
@ComponentScan           // 组件扫描
```

## 三、Spring MVC

### 7. Spring MVC 执行流程 ⭐⭐⭐

**Q: Spring MVC 执行流程？**

```
1. 用户发送请求 → DispatcherServlet
2. DispatcherServlet → HandlerMapping（找 Controller）
3. HandlerMapping → 返回 HandlerExecutionChain
4. DispatcherServlet → HandlerAdapter（执行 Controller）
5. HandlerAdapter → Controller（执行业务逻辑）
6. Controller → 返回 ModelAndView
7. DispatcherServlet → ViewResolver（解析视图）
8. ViewResolver → 返回 View
9. View → 渲染页面
10. 返回响应
```

**Q: DispatcherServlet 的作用？**

核心控制器，处理所有请求，是 Spring MVC 的入口。

**Q: 核心组件有哪些？**

| 组件 | 说明 |
|------|------|
| DispatcherServlet | 前端控制器 |
| HandlerMapping | 处理器映射 |
| HandlerAdapter | 处理器适配器 |
| Controller | 控制器 |
| ViewResolver | 视图解析器 |
| View | 视图 |

### 9. 异常处理 ⭐⭐

**Q: 如何进行全局异常处理？**

        return ResponseEntity.status(500).body("服务器错误");
    }
}

## 四、Spring Data JPA

### 10. JPA 核心概念 ⭐⭐

**Q: 什么是 JPA？**

JPA（Java Persistence API）是 Java EE 标准的一套 ORM 规范。

**Q: JPA 和 MyBatis 的区别？**

| 特性 | JPA | MyBatis |
|------|-----|---------|
| 开发效率 | 高 | 中 |
| SQL 控制 | 自动 | 手动 |
| 灵活性 | 中 | 高 |
| 性能 | 中 | 高 |

**Q: 关联类型？**

| 类型 | 注解 |
|------|------|
| 一对一 | `@OneToOne` |
| 一对多 | `@OneToMany` |
| 多对一 | `@ManyToOne` |
| 多对多 | `@ManyToMany` |

**Q: FetchType 类型？**

| 类型 | 说明 |
|------|------|
| `LAZY` | 延迟加载（推荐） |
| `EAGER` | 立即加载 |

## 五、Spring Security

### 11. 认证和授权 ⭐⭐

**Q: 认证和授权的区别？**

- **认证**：验证你是谁（登录）
- **授权**：验证你能做什么（权限）

**Q: 认证流程？**

1. 用户提交认证信息
2. `AuthenticationManager` 进行认证
3. `UserDetailsService` 加载用户详情
4. `PasswordEncoder` 验证密码
5. 认证成功，将 `Authentication` 存入 `SecurityContext`

**Q: JWT 和 Session 的区别？**

| 特性 | JWT | Session |
|------|-----|---------|
| 存储 | 客户端 | 服务器 |
| 无状态 | 是 | 否 |
| 跨域 | 容易 | 困难 |
| 服务器压力 | 低 | 高 |

## 七、常见问题

### 14. Bean 循环依赖 ⭐⭐

**Q: 什么是循环依赖？**

A 依赖 B，B 依赖 A。

**Q: Spring 如何解决循环依赖？**

- 通过三级缓存解决
- 只能解决单例 Bean 的 Setter 注入
- 构造器注入无法解决循环依赖

### 15. @Component、@Service、@Repository、@Controller 的区别？ ⭐⭐

| 注解 | 用途 |
|------|------|
| `@Component` | 通用组件 |
| `@Service` | Service 层 |
| `@Repository` | DAO 层 |
| `@Controller` | Controller 层 |

**本质相同，语义不同，便于 AOP 区分处理。**

### 16. @Autowired 和 @Resource 的区别？ ⭐

| 特性 | @Autowired | @Resource |
|------|-----------|----------|
| 来源 | Spring | JDK |
| 匹配方式 | byType、byName | byName、byType |
| 是否必需 | 可设为 false | 无 |
