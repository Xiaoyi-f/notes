# 02 - GPIO、ADC、PWM、中断——嵌入式设备的"五官和手脚"

---

## 一、GPIO（通用输入输出）—— 设备的"手"

GPIO 是嵌入式设备与外界交互最基本的接口。你可以把它理解为电灯的开关。

### 数字信号 vs 模拟信号

```
数字信号（Digital）：只有两种状态
  高电平（HIGH / 1 / 3.3V） ───────┐
  低电平（LOW / 0 / 0V）    ───────┘

  波形：┌──┐  ┌──┐  ┌──┐
       │  │  │  │  │  │
       └──┘  └──┘  └──┘

  用途：按钮按下/松开、LED亮/灭、继电器开/关


模拟信号（Analog）：连续的电压值
  0V ──────────────────────────────────
                    /
                   /
  1.65V ────────/─────────────────────
                /
               /
  3.3V ─────/─────────────────────────

  用途：温度（-40°C~80°C对应0V~3.3V）、光线亮度
```

### GPIO 输入模式——读取外部状态

```c
// 嵌入式端代码（ESP32/Arduino风格）
// 配置GPIO2为输入模式，接上拉电阻
pinMode(2, INPUT_PULLUP);

void loop() {
  int state = digitalRead(2);  // 读取引脚状态
  if (state == LOW) {
    Serial.println("按钮按下了！");
  }
}
```

**你（全栈端）需要知道的**：
- 按钮按下 = GPIO读取到低电平（LOW）
- 按钮松开 = GPIO读取到高电平（HIGH）
- 嵌入式设备会把这个状态通过 UART/MQTT 上报给你

```
数据流：
按钮按下 ──► GPIO2变LOW ──► 嵌入式检测到 ──► 通过MQTT上报
                                                    │
                                                    ▼
                                              ┌──────────┐
                                              │  你的App  │
                                              │ "检测到   │
                                              │  按钮按下"│
                                              └──────────┘
```

## 二、ADC（模数转换器）—— 设备的"感官"

ADC 把连续的模拟电压转换成数字值，让芯片能"感知"温度、光线、压力等物理量。

### 原理

```
传感器（如温度探头）输出 0~3.3V 的电压
                           │
                           ▼
                    ┌──────────────┐
                    │     ADC      │
                    │  0V   →  0   │
                    │  1.65V → 2048│  (12位ADC，范围0~4095)
                    │  3.3V  → 4095│
                    └──────────────┘
                           │
                           ▼
                    数字值（0~4095）
                           │
                           ▼
                    你的程序换算成实际温度

换算公式：
温度 = (ADC值 / 4095) * (最高温度 - 最低温度) + 最低温度
```

### 实际例子：读取温度

```c
// 嵌入式端
const int tempPin = 34;  // ESP32的GPIO34接温度传感器

void readTemperature() {
  int adcValue = analogRead(tempPin);        // 读取ADC值（0~4095）
  float voltage = adcValue * 3.3 / 4095.0;   // 换算成电压
  float temperature = voltage * 100;          // 传感器特性：1V = 100°C

  Serial.print("温度：");
  Serial.print(temperature);
  Serial.println("°C");
}
```

### ADC 精度

| ADC位数 | 范围 | 精度（3.3V满量程） | 应用场景 |
|---------|------|-------------------|---------|
| 8位 | 0~255 | 约 13mV | 粗略测量 |
| 10位 | 0~1023 | 约 3.2mV | 一般测量 |
| 12位 | 0~4095 | 约 0.8mV | 精细测量（ESP32默认） |
| 16位 | 0~65535 | 约 0.05mV | 高精度测量 |

**你（全栈端）需要知道的**：
- ADC有精度限制，不要期望小数点后很多位都准
- 传感器有噪声，嵌入式端通常会做"平均值滤波"
- 你收到的数据已经是处理后的数字，不需要再理解ADC细节

## 三、PWM（脉冲宽度调制）—— 设备的"调节器"

PWM 用快速的开关信号来模拟不同的输出强度，控制LED亮度、电机转速等。

### 原理

```
PWM = 高电平时间占整个周期的比例

周期 = 20ms（频率50Hz）

100% 占空比（最亮/最快）：
┌────────────────────────────────────┐
│████████████████████████████████████│  ← 全是高电平
└────────────────────────────────────┘

50% 占空比（中等亮度/中等速度）：
┌────────────────┐        ┌────────────────┐
│████████████████│        │████████████████│
└────────────────┘        └────────────────┘
  高电平10ms              低电平10ms

10% 占空比（很暗/很慢）：
┌──┐                                  ┌──┐
│██│                                  │██│
└──┘                                  └──┘
  高电平2ms    低电平18ms

0% 占空比（关闭）：
                                    
                                    ← 全是低电平
                                    
```

### 控制LED亮度

```c
// 嵌入式端
const int ledPin = 2;

void setup() {
  ledcSetup(0, 5000, 8);        // 通道0，频率5kHz，8位精度
  ledcAttachPin(ledPin, 0);     // 绑定GPIO2到通道0
}

void setBrightness(int brightness) {
  // brightness: 0~255
  ledcWrite(0, brightness);
}

// 使用
setBrightness(255);  // 最亮
setBrightness(128);  // 一半亮度
setBrightness(0);    // 关闭
```

**你（全栈端）需要知道的**：
- 你发指令给设备：`{"led": 2, "brightness": 128}`
- 设备收到后调用 `setBrightness(128)`
- PWM 精度由嵌入式端控制（通常是8位=0~255）

## 四、中断（Interrupt）—— 设备的"紧急呼叫"

### 什么是中断？

正常情况，程序按顺序一行一行执行：

```
正常执行流程：
第1行 ──► 第2行 ──► 第3行 ──► 第4行 ──► 第5行 ──► ...
```

但如果有紧急事件（比如按钮突然按下），程序需要立刻处理：

```
带中断的执行流程：
第1行 ──► 第2行 ──► [按钮按下！中断！] ──► 跳去处理中断 ──► 回到第3行继续
```

### 为什么用中断？

```
不用中断的写法（轮询）：
while (true) {
  if (按钮按下了) {     // 每秒检查1000次，浪费电
    处理按钮事件
  }
  做其他事情
  delay(1);
}

用中断的写法：
void setup() {
  attachInterrupt(digitalPinToInterrupt(2), onButtonPress, FALLING);
  // 按钮引脚，处理函数，触发条件（下降沿=按下瞬间）
}

void loop() {
  做其他事情        // 不需要管按钮，有中断会自动处理
}

void onButtonPress() {
  处理按钮事件      // 只有按钮按下时才会执行，省电！
}
```

### 中断触发条件

| 触发方式 | 说明 | 例子 |
|---------|------|------|
| RISING | 上升沿（低→高） | 按钮松开瞬间 |
| FALLING | 下降沿（高→低） | 按钮按下瞬间 |
| CHANGE | 电平变化 | 按下和松开都触发 |
| LOW | 低电平持续 | 按钮一直按着 |

**你（全栈端）需要知道的**：
- 中断处理函数里不能做太多事情（要快！）
- 通常只是设置一个标志位，主循环里再处理
- 中断里不要用 `delay()`，不要打印大量日志
- 如果你发指令给设备，设备可能在处理中断，响应会延迟

---

## 五、四种接口的对比总结

| 接口 | 作用 | 你的角色 | 数据方向 |
|------|------|---------|---------|
| **GPIO** | 开关控制 | 发指令让设备开/关 | 双向 |
| **ADC** | 读取传感器 | 接收设备上报的数据 | 设备→你 |
| **PWM** | 调节强度 | 发指令调节亮度/速度 | 你→设备 |
| **中断** | 紧急事件 | 设备主动通知你有事 | 设备→你 |
