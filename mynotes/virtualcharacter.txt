# 第一部分：3D虚拟人建模、绑定、动画（模型源头）
虚拟人能做动作、表情、对口型，**核心前提是模型做好「骨骼绑定+形态目标(BlendShape)」**，只做裸模型无法交互。

## 一、主流软件细分、定位、必学技能
### （一）专业手工建模（从零制作高精度虚拟人）
#### 1. Blender（首选，免费开源，全流程通吃，独立开发者/个人必学）
##### 软件定位
建模、雕刻、UV、材质、骨骼绑定、动画、渲染一站式工具，**网页虚拟人最主流产出工具**，导出的GLB/GLTF是网页标准格式。
##### 必须掌握的核心技能（按优先级）
1. **基础建模**
   - 多边形建模：点/线/面编辑、环切、挤出、倒角、拓扑优化（网页模型必须减面，否则卡顿）
   - 人体布线规范：面部、关节布线要符合肌肉运动逻辑，不然后续动画变形穿模
2. **UV展开**
   - 全身+面部UV拆分、UV排布、纹理拉伸修正
   - 作用：贴图（皮肤、衣服、妆容）正常显示，网页渲染必备
3. **材质与贴图**
   - PBR物理材质（基础色、法线、粗糙度、金属度），网页3D引擎只认PBR
   - 贴图烘焙：高模细节烘焙到低模（提升质感、控制面数）
4. **雕刻（进阶）**
   - 笔刷使用、细节雕刻（皮肤纹理、五官细节），搭配ZBrush工作流也需掌握基础雕刻
5. **骨骼绑定（重中之重，动作基础）**
   - 骨架创建：全身IK/FK骨骼（头、躯干、四肢、手指）
   - 权重绘制：让骨骼能带动网格运动，权重错误会出现肢体扭曲、穿模
   - 绑定规范：适配网页实时渲染，骨骼数量不宜过多
6. **形态目标 BlendShape（口型+表情核心）**
   - 制作基础表情：眨眼、微笑、皱眉、惊讶
   - 制作**Viseme口型**（15组标准口型，对应拼音/英文发音，唇形同步必备）
7. **动画制作**
   - 关键帧动画：制作待机、挥手、点头、转身等**循环动作库**
   - 动作剪辑、动画混合（多个动作无缝切换）
8. **导出优化**
   - 导出 `GLB/GLTF`（网页首选）、FBX
   - 模型减面、贴图压缩、动画裁剪（网页性能优化核心）

##### 学习梯度
- 入门：基础建模+UV+简单材质
- 进阶：骨骼绑定+BlendShape表情/口型+基础动画
- 精通：权重精细调整、多动画混合、模型极致轻量化、批量导出配置

#### 2. Maya（行业标准，商用虚拟人/虚拟偶像主力）
##### 软件定位
影视、游戏、商用虚拟人标杆软件，**角色绑定、面部动画、动作调优生态最强**，大厂团队主流使用。
##### 必学技能
- 多边形建模、UV、贴图、PBR材质（和Blender逻辑互通）
- 高级骨骼系统：角色装配、IK/FK切换、控制器制作
- 面部绑定系统：面部骨骼+BlendShape组合（超精细表情）
- 动画模块：角色动画、动捕数据导入与修复
- 格式导出：FBX/GLB，对接网页引擎

> 补充：个人开发优先学Blender，团队/商业项目建议补充Maya。

#### 3. ZBrush（高精度细节雕刻，辅助工具）
##### 软件定位
只做**高模细节**，不做动画和绑定，属于流程上游工具。
##### 必学技能
- 基础笔刷、模型雕刻：人脸、皮肤、服饰、肌理细节
- 拓扑重构：高模转低模（网页必须用低模）
- 贴图烘焙：法线贴图、AO贴图（把高模细节贴到低模上，兼顾质感和性能）

##### 标准工作流（手工高精度虚拟人）
`ZBrush雕刻高模` → `Blender/Maya拓扑低模+UV` → `烘焙贴图` → `PBR材质` → `骨骼绑定+BlendShape口型/表情` → `制作动作动画` → `轻量化导出GLB`

### （二）AI快速生成虚拟人（零建模基础快速出模型，项目提速必备）
适合不想从零建模、快速搭建原型、批量生成虚拟人场景，生成后仍需简单绑定/优化才能用于网页交互。

#### 1. MetaHuman（Epic 虚幻引擎）
- 定位：**超写实真人级虚拟人**，商用虚拟主播、数字分身首选
- 必学内容：
  1. 人像参数调节：五官、发型、肤色、服饰快速定制
  2. 内置资源使用：自带全套骨骼、上百种面部表情+标准Viseme口型、基础动作库
  3. 模型导出：从UE导出FBX/GLB，导出前做面数精简、动画筛选
  4. 后处理：导入Blender修正权重、优化贴图，适配网页渲染
- 优势：开箱即用表情、口型、骨骼，省去80%绑定工作量

#### 2. Ready Player Me
- 定位：轻量卡通/写实头像、全身虚拟人，**网页生态适配度最高**
- 必学内容：
  1. 照片生成/手动捏人，快速生成全身角色
  2. 直接导出标准GLB模型（自带骨骼、基础表情）
  3. 模型二次优化：减面、补充自定义动作
- 优势：导出格式原生支持Three.js，个人项目原型首选

#### 3. NeRF（神经辐射场，照片重建3D真人）
- 定位：基于多张2D照片AI重建**真人实景3D模型**，偏向视觉复刻
- 必学内容：
  1. 照片采集规范、开源NeRF框架使用（Instant NGP、SDF-NeRF等）
  2. NeRF模型转传统网格模型（Mesh提取）—— 关键一步，纯NeRF无法做骨骼动画
  3. 网格修复、拓扑、绑定，转为可驱动的动画模型
- 适用场景：真人数字分身，学习门槛偏高，属于进阶技术

### 三、建模板块「精通」验收标准
1. 能从零完成**低面数可交互虚拟人**：建模→UV→材质→骨骼绑定→权重→口型/表情→动作动画→GLB轻量化导出
2. 能对AI生成的虚拟人做二次修改、绑定、性能优化
3. 理解网页端模型性能限制：面数、骨骼数、贴图尺寸的取舍规则

# 第二部分：前端 3D 渲染（网页加载、展示、驱动虚拟人动作/口型）
模型做好后，需要前端3D引擎在浏览器渲染，并**实时接收后端指令，驱动骨骼、表情、口型**。主流两大框架：Three.js、Babylon.js，国内90%项目用 **Three.js**。

## 一、前置基础（必须先掌握）
### 1. 前端通用基础（底层，绕不开）
1. **HTML/CSS**：页面布局、UI、弹窗、麦克风按钮、视频容器等
2. **JavaScript / TypeScript**：核心编程语言，所有3D逻辑、通信逻辑都基于JS
   - 重点：ES6+语法、异步编程(Promise/async/await)、事件监听、数据流转
3. **浏览器原生API**
   - `MediaDevices`：调用麦克风、采集音频流（语音对话入口）
   - `Web Audio API`：播放TTS合成的语音、音频解析
   - `WebSocket`：前后端实时通信（核心，传递语音、口型、动作数据）

### 2. 计算机图形学基础（精通必备，理解原理）
不用深挖学术公式，但必须懂概念：
- 3D坐标系、相机、灯光、透视投影
- 网格(Mesh)、材质(Material)、纹理(Texture)
- 骨骼动画原理、蒙皮权重、动画状态机
- BlendShape（形态目标）驱动原理（口型/表情的底层逻辑）
- 网页渲染性能：帧率、DrawCall、面数、贴图大小优化

## 二、核心框架：Three.js（重点精讲）
### 1. 基础核心模块（入门必学）
1. **三大件**：场景(Scene)、相机(Camera)、渲染器(Renderer)
   - 场景管理：添加/移除模型、灯光、环境
   - 相机控制：轨道控制器(OrbitControls)、视角锁定
   - 渲染器配置：抗锯齿、背景、像素比、适配移动端
2. **模型加载**
   - `GLTFLoader`：加载项目主流的GLB/GLTF模型（重中之重）
   - 模型解析：获取场景对象、骨骼(Skeleton)、动画(Animation)、形态目标(MorphTarget)
3. **基础动画**
   - `AnimationMixer` 动画混合器：控制模型所有动画
   - 播放/暂停/切换循环动作（待机、挥手、点头等预录动作）
   - 动画权重混合：多个动作平滑过渡

### 2. 交互核心模块（实现「动作+口型」，进阶必学）
#### （1）形态目标控制 → 驱动表情+Viseme口型
虚拟人说话的口型、喜怒哀乐表情，全部靠 `MorphTargetInfluences` 控制：
- 原理：Blender/Maya里做好多组面部形态，前端通过**数值(0~1)** 切换形态
- 实战：接收后端传来的 `viseme编号`，实时修改对应形态权重，实现唇形同步

#### （2）骨骼实时驱动 → 自定义肢体动作
两种方案：
1. **预录动作库（主流，简单稳定）**
   后端根据对话情绪，下发「动作ID」，前端播放对应预设动画（开心→挥手、严肃→站立）
2. **实时骨骼驱动（高阶）**
   后端/动捕系统下发骨骼旋转/位移数据，前端逐帧修改骨骼姿态，实现自定义动作

#### （3）音频联动
- 同步播放后端返回的TTS语音
- 音频播放进度 和 口型动画 时间对齐（解决“音画不同步”）

### 3. 网络通信（前后端数据互通）
1. **WebSocket**（首选，长连接、低延迟）
   - 前端建立WS连接，持续推送麦克风音频流
   - 接收后端回传：文本回复、音频流、viseme口型数据、动作ID、表情参数
2. 备选：HTTP（短连接），仅适合低实时性场景，**虚拟人对话不推荐**

### 4. 性能优化（精通必备，网页不卡顿的关键）
- 模型优化：GLB压缩、面数精简、合并网格
- 贴图优化：贴图尺寸压缩、格式转换(WebP)、Mipmap
- 渲染优化：合理灯光、关闭不必要特效、动画帧节流
- 兼容：PC/移动端适配、低端设备降级策略

## 三、备选框架：Babylon.js
- 定位：微软出品，内置功能更全，物理引擎、动画系统、编辑器原生支持
- 适用：大型商用项目、需要复杂物理交互的虚拟人
- 学习逻辑和Three.js高度相似，会其一可快速上手另一个

## 四、前端板块「精通」验收标准
1. 独立完成：GLB虚拟人加载、灯光相机配置、页面布局
2. 熟练控制：动画播放/切换、BlendShape口型/表情实时驱动
3. 实现：WebSocket音频流传输、音画同步、解决音画不同步、动画卡顿问题
4. 完成全链路：麦克风采集 → 接收后端数据 → 虚拟人「说话+做动作+变表情」

# 第三部分：AI交互后端（听、想、说、动作逻辑中枢）
整个系统的**大脑**，串联「语音识别→对话理解→语音合成→动作指令生成」，分为5大核心模块：`ASR语音识别`、`LLM大模型对话`、`TTS语音合成`、`唇形同步`、`动作/表情调度`。

## 一、后端前置基础
1. **后端编程语言&框架**（二选一，主流组合）
   - 方案1：Python（最适合AI生态）+ FastAPI/Flask（轻量高性能接口）
   - 方案2：Node.js + Express（和前端JS技术栈统一，WebSocket更顺手）
2. **网络通信**
   - WebSocket 服务端开发：接收前端音频流、下发结构化数据（二进制/JSON）
   - 流式数据处理：音频分片、流式传输（低延迟核心）
3. **基础工程能力**
   - 接口封装、日志、异常处理、并发处理（多人同时访问）
   - 服务部署：Linux服务器、进程守护、端口配置

## 二、五大核心AI模块（逐个拆解技能+工具）
### 模块1：ASR 自动语音识别（听：语音 → 文字）
#### 功能
用户对着麦克风说话 → 音频流转成文本，传给大模型。
#### 必学技术&工具
1. **开源本地部署（推荐学习，私有化部署）**
   - Whisper（OpenAI）：全球最主流，支持多语言、方言，模型大小可选（tiny/base/large）
   - SenseVoice：国内开源，中文识别效果优于Whisper，轻量高效
   - 技能：音频格式转换、流式ASR（边说边转，非整段识别，降低延迟）
2. **云API（快速落地项目，不用训练）**
   - 阿里云、腾讯云、百度智能云语音ASR接口调用
#### 精通要求
- 实现**流式实时语音识别**，断句、静音检测（没人说话自动暂停）
- 处理音频编码、采样率适配（浏览器音频格式和模型要求对齐）

### 模块2：LLM 大语言模型（想：文字 → 对话回复）
#### 功能
接收ASR文本 → 理解语义、上下文对话、生成自然回复文本，同时输出**情绪标签**（开心/平静/惊讶/严肃）。
#### 必学技术&工具
1. **大模型使用分类**
   - 商用API：通义千问、文心一言、讯飞星火、GPT-4o（调用简单，开箱即用）
   - 开源本地部署：Qwen、Llama3、ChatGLM、Phi系列（私有化、无调用费用，进阶必学）
2. **核心技能**
   - Prompt工程：设定虚拟人人设、对话规则、上下文记忆（多轮对话）
   - 对话状态管理：历史对话存储、上下文截断（防止token过长）
   - 结构化输出：让LLM固定格式返回 `回复文本 + 情绪标签`（给后续动作/表情使用）
   - 流式输出：逐字返回文本，配合TTS实现“边生成边播报”

### 模块3：TTS 语音合成（说：文字 → 语音）
#### 功能
LLM生成的文本 → 转为自然人声音频，同时输出**Viseme口型时间戳**（唇形同步核心数据）。
#### 必学技术&工具
1. **开源本地部署**
   - VITS、Diff-SVC、Fish Speech：主流开源语音合成，支持音色克隆、情感调节
2. **云API**
   - 阿里云TTS、讯飞TTS、ElevenLabs（海外音色自然度顶尖）
3. **关键能力（精通核心）**
   - **Viseme提取**：TTS输出音频 + 对应时间轴的口型编号（0~14标准口型）
   - 情感语音合成：根据LLM的情绪标签，改变语音语速、音调、语气
   - 流式TTS：逐段生成音频，降低整体延迟

### 模块4：Lip-Sync 唇形同步（对口型：音频 → 口型动画）
#### 功能
把TTS音频/Viseme数据，转为前端可识别的口型指令。
#### 两种主流方案（按需学习）
1. **方案A：Viseme映射（简单、稳定，项目首选）**
   - 流程：TTS直接输出 `[时间, 口型编号]` 数组 → 通过WebSocket传给前端
   - 前端根据编号驱动BlendShape，实现口型匹配
   - 学习成本低，工业界主流方案
2. **方案B：音频驱动口型（高阶，无预定义口型也能用）**
   - 工具：Wav2Lip、SadTalker（开源AI唇形驱动）
   - 原理：直接分析音频波形，自动生成面部运动数据
   - 适用：模型没有提前制作Viseme口型的场景，算力要求更高

### 模块5：动作&表情调度（动：情绪 → 肢体/表情）
#### 功能
根据LLM返回的**情绪、对话内容**，自动分配动作、表情。
#### 分层技术（从入门到精通）
1. **入门：动作映射表（最简单）**
   - 建立规则：情绪=开心 → 播放挥手动作+微笑表情；情绪=严肃 → 站立待机
   - 后端下发「动作ID+表情ID」，前端执行，90%常规项目用这套
2. **进阶：动作随机化+过渡**
   - 同情绪下随机切换多个动作，避免机械重复
   - 动作之间添加过渡动画，不生硬
3. **高阶：AI实时动作生成（前沿技术）**
   - 工具：Motion Diffusion、HumanML3D等动作生成模型
   - 输入文本/情绪，AI实时生成全新肢体动作，适合高端虚拟人

## 三、后端板块「精通」验收标准
1. 串联全链路：ASR → LLM → TTS → 口型/动作数据 完整流转
2. 实现**低延迟流式交互**（端到端延迟控制在1s内）
3. 支持多轮上下文对话、情绪识别、自动分配动作表情
4. 可独立部署全套开源AI模型（Whisper+Qwen+VITS），完成私有化部署

# 第四部分：全链路整合、工程化、部署（最终打通所有环节）
## 一、完整数据流总复盘（从头到尾）
```
1. 用户说话 → 浏览器麦克风采集音频流
2. 前端(Three.js) → WebSocket → 后端：推送音频流
3. 后端ASR(Whisper)：音频 → 文本
4. 后端LLM(大模型)：文本+上下文 → 回复文本 + 情绪标签
5. 后端TTS(VITS)：回复文本 → 语音音频 + Viseme口型时序数据
6. 动作调度模块：根据情绪 → 分配动作ID、表情参数
7. 后端 → WebSocket → 前端：下发 音频流+口型数据+动作ID+表情数据
8. 前端：播放音频 + 驱动虚拟人口型/表情/肢体动作
9. 循环往复，实现实时对话交互
```

## 二、工程化&部署（上线必备技能）
1. **服务器基础**：Linux 常用命令、Nginx反向代理、端口管理
2. **服务部署**：前后端分离部署、AI模型部署、进程守护
3. **容器化（进阶）**：Docker 打包全套服务，一键部署、环境隔离
4. **压力测试**：多用户并发访问测试、延迟优化、故障排查

# 第五部分：分阶段学习路线（从入门 → 精通，规划顺序）

## 阶段5：全链路联调+优化（2个月+，走向精通）

- 前端向：Three.js 深度优化、复杂交互、渲染特效
